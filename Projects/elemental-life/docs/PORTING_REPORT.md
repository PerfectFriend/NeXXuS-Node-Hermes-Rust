## Выполненные шаги

### 1. Инициализация Capacitor-проекта ��
- Проект создан в `elemental-life-app/` с Vite + React + TypeScript
- Capacitor настроен (`npx cap init`, `npx cap add android`)
- Android-проект синхронизирован (`npx cap sync android`)

### 2. Перенос игрового движка ������ **Требует внимания**
- `src/engine/engine.ts` — порт `src/engine.js` на TypeScript
- Smoke-тест проходит: **10/10 пресетов** (5 hex + 5 square) — закон сохранения воды держится на 500 тиках
- **ВАЖНОЕ ОТКЛОНЕНИЕ**: TypeScript-версия содержит **дополнительную логику**, отсутствующую в оригинальном `engine.js`:
  - **Flow-логика** (строки 530-571): вода течёт в пустоту через 2 тика (`flowTargets`, `flowReverse`, `flowSources`)
  - **Terraforming-логика** (строки 573-642): пустые клетки, окружённые землёй+жизнью, ищут воду BFS и забирают её
  - **Троттлинг overflow** (строка 645): проверка перелива воды только каждый 3-й тик
  - **Жёсткий код для пепла**: `wetStreak >= 3` вместо `params.ashToEarthTicks`
  - **Разные правила терраформирования** для hex vs square (строки 590-594)
- **Разные параметры puzzle-режима**:
  - `PUZZLE_RADIUS`: TS={hex:12, square:10} vs JS={hex:8, square:6} → поле 469/441 клеток вместо 217/169
  - `GEOMETRY_LEVELS.droplets`: TS значительно выше (80-175 vs 55-115 для hex; 60-150 vs 38-93 для square)
- **Влияние**: Smoke-тест (water conservation) проходит, но **динамика симуляции и баланс уровней изменены**. headless-тесты на 3000+ тиков для проверки плато популяции жизни **не запускались** для TS-версии.
- **Рекомендация**: Вернуть TS-движок к точному соответствию JS-оригналу (убрать flow/terraforming, вернуть PUZZLE_RADIUS и LEVELS из JS) перед финальным релизом. См. `GAME_DESIGN.md` — историю находок багов, которые легко вернуть при изменении логики.

### 3. UI на Canvas ��
- `GridRenderer.ts` — низкоуровневый Canvas-рендерер для hex и square сеток
- `GridCanvas.tsx` — React-обёртка с RAF-циклом и двусторонней синхронизацией viewport
- Поддержка жестов: pinch-зум, панорамирование (pointer events), колесо мыши
- Фикс race condition при центрировании (ignoreNextSync flag)

### 4. Переключатель геометрии при старте новой игры ��
- Добавлен `NewGameDialog.tsx` — трёхшаговый диалог:
  1. Выбор геометрии (hex / square) с показом реального числа клеток
  2. Выбор режима (песочница / головоломка)
  3. Выбор пресета (только для песочницы, 5 пресетов на геометрию)
- Интегрирован в `App.tsx` вместо прямого сброса поля

## Известные проблемы / Технический долг

1. **TS-движок расходится с JS-оригналом** — см. раздел "Перенос игрового движка" выше. Это главная техническая проблема.
2. **Dynamic import warning** — `engine.ts` динамически импортируется в `instagram-readonly-parser`, но также статически во множестве мест. Не влияет на работу, но увеличивает bundle.
3. **Gradle deprecation warnings** — используются устаревшие API, несовместимые с Gradle 9.0. Требуется миграция при обновлении.
4. **APK подпись** — текущая debug-сборка не подписана для Play Store. Для релиза нужна настройка `signingConfigs` в `android/app/build.gradle`.
5. **Размер поля в SettingsModal** — показывает жестко заданные числа (2611/469 для hex, 841/441 для square), а не вычисляет через `gridCellCount`. Нужно привести к единому источнику истины.

## Архитектурные решения

### Монорепо структура
```
elemental-life/
├── src/engine.js              # Оригинальный JS движок (reference, source of truth)
├── tests/engine.smoke.test.mjs # Smoke-тест для JS
├── reference/                 # React-артефакт-референс
├── docs/                      # GAME_DESIGN.md, PORTING_PLAN.md
��── elemental-life-app/        # Capacitor-проект
    ├── src/
    │   ├── engine/engine.ts   # TypeScript порт движка (ТРЕБУЕТ ИСПРАВЛЕНИЯ)
    │   ├── renderer/GridRenderer.ts
    │   ├── hooks/useSimulation.ts
    │   ├── components/
    │   │   ├── GridCanvas.tsx
    │   │   ├── NewGameDialog.tsx  ← НОВОЕ
    │   │   └── ...
    │   └── App.tsx
    └── android/               # Android-проект
```

### Ключевые паттерны
- **Platform-agnostic engine** — `engine.ts` не зависит от React/DOM/Canvas
- **Viewport sync** — двусторонняя синхронизация между React и Canvas-рендерером через `ignoreNextSync` для предотвращения race conditions
- **Geometry-first UX** — выбор геометрии один раз при старте новой игры, как смена уровня в puzzle
