# План портирования

## Текущее состояние

Игровое ядро (`src/engine.js`) уже отделено от UI и не зависит от React,
DOM или какого-либо фреймворка. Он принимает `Map` (состояние поля) и
объект параметров, возвращает новый `Map`. Это значит, что **самая
сложная часть (логика стихий) почти не требует доработки** при переносе
на любую платформу — придётся переписать только слой рендеринга и
обработки ввода.

## Рекомендуемый путь: Capacitor + Canvas

Дано, что разработчик (пользователь) уже работает с Capacitor в других
проектах (мобильные мессенджеры с Tor-интеграцией) — естественно
продолжить на этом же стеке, а не осваивать новый.

### Шаги:

1. **Инициализация Capacitor-проекта** (`npm create vite@latest` с
   React-шаблоном, затем `npx cap init`, `npx cap add android`).
2. **Перенос `src/engine.js` без изменений** в новый проект.
3. **Переписать рендер**: вместо SVG-полигонов (которые в референсе
   рендерят до 2611 DOM-элементов на каждый тик — нормально для
   браузера, тяжело для слабого Android-устройства) — использовать
   `<canvas>` с прямой растровой отрисовкой гексагонов. Один `canvas`
   с ручной отрисовкой через `ctx.fill()` в цикле существенно быстрее
   на мобильных GPU/CPU, чем тысячи DOM-нодов.
4. **Жесты**: заменить текущие `onWheel`/`onMouseDown`/`onTouchStart`
   обработчики на `react-native-gesture-handler` (если перейти на
   React Native) или оставить нативные DOM Pointer Events (если
   остаться на Capacitor WebView — там обычные web-жесты работают
   нормально, Capacitor — это WebView, а не RN).
5. **Тики симуляции**: текущий `setInterval` в `useEffect` достаточен;
   рекомендуется профилировать `stepField` на реальном среднем
   Android-устройстве (не флагмане) — на поле 2611 клеток
   с overflow-логикой (проверка "соседей соседей") это самая дорогая
   операция за тик. Если будет проседать — варианты:
   - Проверять overflow не каждый тик, а раз в N тиков.
   - Вынести `stepField` в Web Worker (он чистая функция без DOM —
     идеально подходит для воркера).
6. **Fullscreen API**: на Android не нужен — приложение само полноэкранное;
   текущий код с `document.fullscreenElement` можно убрать из мобильной
   сборки или оставить как no-op (Capacitor сам решает полноэкранность
   через нативную конфигурацию).
7. **Сборка APK/AAB**: `npx cap sync android`, затем открыть
   `android/` в Android Studio, настроить подпись релиза, собрать AAB
   для загрузки в Google Play Console.

## Альтернатива: Godot (если рассматривается и Steam/PC)

Если есть интерес выйти не только на Android, но и на Steam/itch.io —
Godot экспортирует из одного проекта на Android, iOS, Windows, Linux, Web.
Логику `stepField` придётся переписать на GDScript (концептуально
тривиально — это конечный автомат с switch/case на 7 состояний), но
зато сразу открывается путь на десктоп без отдельного проекта.
Минус — больше единоразовой работы по переносу UI, так как Godot не
переиспользует существующий React-код вообще.

## Чего НЕ делать

- Не пытаться обернуть текущий React-Artifact-компонент в WebView "as is"
  без переработки рендера — производительность SVG с 2611 элементами
  на слабом Android-устройстве не гарантирована, и зум/панорамирование
  через CSS transform может работать рывками на старых GPU WebView.
- Не переносить puzzle-уровни (`LEVELS` в `engine.js`) без повторной
  проверки баланса на целевой платформе, если меняется размер поля
  (`PUZZLE_RADIUS`) — баланс калибровался headless-тестами именно под
  217 клеток; смена размера поля требует пересчёта.
