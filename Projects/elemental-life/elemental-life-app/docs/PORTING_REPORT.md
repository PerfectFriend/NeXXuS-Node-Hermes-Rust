# PORTING REPORT

## Статус проекта (v2.4)

### Выполнено

1. **Capacitor-проект** на базе Vite + React + TypeScript — сборка через `npx cap sync android` и `./gradlew assembleDebug`.

2. **Движок `src/engine/engine.ts`** — перенесён без изменения логики оригинальных правил. Добавлены:
   - **Правило 1 — перелив воды**: вода, соседствующая с пустотой 2 тика подряд, становится землёй; целевая пустота становится водой. Отслеживается через `flowTicks` на клетке воды.
   - **Правило 2 — терраформинг**: пустота, полностью окружённая землёй и жизнью (соотношения 2E+4L / 3E+3L / 4E+2L для гекса; 3E+5L / 4E+4L / 5E+3L для квадрата), запускает BFS (до глубины 12) для поиска ближайшей воды. Найденная вода становится землёй, пустота становится водой.

3. **Закон сохранения воды**: smoke-тест (10/10 пресетов, hex+square, 500 тиков) проходит. Исправлены:
   - Гонка при consumed-by-fire: если источник воды был поглощён огнём (→ пар), целевая пустота НЕ становится водой (иначе вода+пар создаётся из ничего).
   - Гонка в BFS: при одновременном терраформинге нескольких пустот, первая нашедшая воду блокирует её (`flowSources.add()` сразу в BFS).
   - Гонка overflow+flow: если оба правила метят одну пустоту, overflow пропускает её (проверка `!flowTargets.has(tKey)`).

4. **Touch zoom**: переписан на Pointer Events с multi-pointer tracking (Map<pointerId, coords>). Пинч-зум по двум пальцам, панорамирование одним.

5. **Canvas-рендер**: гексагональная сетка (pointy-top), квадратная сетка, обе геометрии.

6. **Android-сборка**: APK (debug, 7.8 MB) собирается и отправляется в Telegram (см. PLAN.md Point 7: sha256 `1fceb322…`, экспорт в `~/apkexport/elemental-life-debug.apk`).

7. **Telegram-бот**: скрипт `poll_bot.ps1` (PowerShell) — long-polling, inline-клавиатуры, команды /build /send /status /smoke /sync. Запускается отдельно.

### Известные проблемы

- **Нельзя менять без запроса**: формулы/пороги в engine.ts, критерий победы (WIN_MAX_AGE, WIN_STABLE_TICKS), параметры пресетов/уровней.
- **Производительность stepField**: на full-size sandbox (2611 клеток) BFS для терраформинга может быть дорогим при большом числе пустот, окружённых E+L. Ограничение глубины BFS = 12.
- **Telegram-бот**: запускается вручную (`pwsh poll_bot.ps1` в корне проекта). При перезагрузке нужно перезапускать.

### Архитектурные решения

- Две геометрии сетки (hex/square) выбираются при старте новой игры, не меняются на лету.
- Новые правила реализованы как pre-pass (анализ поля) + main loop (применение), аналогично overflow.
- Сохранение воды обеспечено строгим контролем: каждая операция flow/terraform/overflow создаёт ровно 1 источник и 1 цель.
- Для предотвращения создания воды из nothing при consumed-by-fire, в pre-pass проверяется, будет ли источник поглощён огнём (наличие соседнего FIRE или LIFE+fire).
