## 📌 Архитектурные Модули Проекта

Приложение разделено на три ключевых логических слоя:

```
[UI Layer (Compose)] <---> [ViewModel (State & Logic)] <---> [Data Layer (Room & Prefs)]
       |
       v
[SimpleX Tor Simulation Engine]
```

### 1. Слой данных (Data Layer)
- **`com.example.db.SimulationDatabase`**: Главный класс базы данных Room, обеспечивающий потокобезопасный доступ к инстансу SQLite.
- **`com.example.db.SavedPresetEntity`**: Схема таблицы для сохранения пользовательских био-пресетов. Хранит состояние шестиугольной сетки в виде оптимизированной CSV-строки.
- **`com.example.db.SavedPresetDao`**: Абстракция доступа к данным с поддержкой асинхронных Flow-запросов (`getAllPresets()`).

### 2. Слой бизнес-логики (Domain & ViewModel Layer)
- **`com.example.viewmodel.SimulationViewModel`**: Главный диспетчер состояний приложения. Управляет:
  - Реактивным тикером симулятора (`startSimulation` / `pauseSimulation`).
  - Вычислениями новых шагов шестиугольной сетки на фоновых потоках Coroutines.
  - Операциями чтения-записи пресетов в базу данных Room.
  - **Био-Цифровым квантовым генератором (`seedFromCryptographicHash`)**: Уникальным алгоритмом воспроизводимого псевдослучайного заселения сетки на основе хэш-кодов строковых параметров.
- **`com.example.model.HexGrid`**: Описывает математическую структуру шестиугольного поля. Содержит логику поиска соседей для каждой ячейки и правила эволюции.
- **`com.example.model.SimRules`**: Конфигурационный класс правил переходов клеток (рождение/смерть при взаимодействии с водой, огнем и травой).

### 3. Слой представления (UI Layer - Jetpack Compose)
- **`com.example.ui.SimulationDashboard`**: Главная панель управления. Содержит рендер интерактивного Canvas шестиугольных ячеек, панель пресетов, слайдеры регулировки скорости и скрытую кнопку перехода в мессенджер.
- **`com.example.ui.SimpleXChatScreen`**: Самодостаточный модуль защищенного мессенджера SimpleX Chat. Реализует:
  - Имитацию бутстрапа и подключения к сети Tor.
  - Сканирование QR-кодов через CameraX (`AndroidView` с биндингом к жизненному циклу Android).
  - Настройки портов SOCKS5 прокси и черных списков недоверенных ретрансляторов.
  - **Интерактивный био-цифровой портал**: Интерфейс для вызова методов мутации сетки симулятора и экспорта текущей экологической телеметрии в текстовый буфер чата.

## 🔬 Ключевые паттерны интеграции (DeepSeek v4 Flash Ready)

При генерации новых функций с использованием движков класса DeepSeek v4 Flash, разработчикам рекомендуется следовать следующим паттернам, заложенным в проекте:

### А. Чтение реактивного состояния сетки
Для минимизации лишних рекомпозиций в Compose, сбор данных из ViewModel осуществляется через `collectAsState` со строгим контролем области видимости:
```kotlin
val gridState by viewModel.gridState.collectAsState()
val generationCount by viewModel.generationCount.collectAsState()
```

### Б. Оптимизация работы с базой данных в Coroutines
Любые дисковые операции записи/удаления пресетов должны выполняться строго в области видимости `viewModelScope` на фоновом пуле диспетчеров:
```kotlin
fun saveCustomPreset(name: String) {
    viewModelScope.launch {
        // Логика конвертации в CSV...
        presetDao.insertPreset(entity)
    }
}
```

## 📈 Перспективные задачи для Контрибьюторов (OpenCode Roadmap)

Если вы хотите внести свой вклад в репозиторий, обратите внимание на следующие приоритетные направления:

1. **Модуль реального Tor-демона (Orbot Integration):**
   - Файл для доработки: `/app/build.gradle.kts`.
   - Задача: Подключить официальную зависимость `org.torproject:tor-android-binary` для развертывания настоящего бинарного файла Tor внутри песочницы приложения и проксирования реального сетевого трафика SimpleX.

2. **Процедурная генерация звука на основе клеточных состояний:**
   - Модуль: `/app/src/main/java/com/example/ui/SimulationDashboard.kt`.
   - Задача: Использовать низкоуровневый `AudioTrack` в Kotlin для генерации синтезированных звуковых волн (Sine wave), частота которых модулируется количеством активных клеток Огня и Воды на экране в реальном времени.

3. **Сквозное шифрование базы данных (SQLCipher):**
   - Класс: `com.example.db.SimulationDatabase`.
   - Задача: Заменить стандартную фабрику Room на шифрующую фабрику `SupportFactory` с генерацией динамического ключа на базе Android Keystore API.
