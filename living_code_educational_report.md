# Living Code Protocol — Образовательный Отчет Агента-Профессора

## Введение
Living Code Protocol — это автономная экосистема эволюционной разработки ПО, где код сам улучшается через итеративные циклы с строгим контролем качества. Протокол запущен 2026-08-15 и сейчас работает в режиме 4-часовых циклов.

## 1. Философия Протокола
> **"Идеальный код рождается в споре. Код, выдержавший 10 подциклов с ≥95% покрытием тестов и без незакоммиченных изменений — ЗАМОРОЖЕН — идеальный, никогда не трогается снова."**

Ключевые принципы:
- Эволюция через конфликт и проверку
- Заморозка идеального кода как неприкосновенного артефакта
- Автоматизированный контроль качества на каждом этапе
- Прозрачность и аудит всех изменений

## 3. Основные Компоненты

### 3.1 Эволюционный Движок (`evolution_engine.py`)
**Назначение:** Выполняет 10 подциклов эволюции на проект за 4-часовой цикл.

**Особенности:**
- Маршрутизация проектов по имени или номеру (1-4)
- Интеграция с Model Registry для оптимального выбора модели
- Цикл: эволюция → тесты → отладка → чекпоинт коммит
- Чекпоинты на подциклах 3, 6, 10
- Автоматическое создание тестов если их нет
- Статический анализ (Ruff + MyPy)
- Git операции: инициализация, коммит, push в приватные репо
- Генерация JSON-отчета за цикл

**Модели:**
- Основная: `nemotron-3-ultra-550b-A55b` (через Model Registry)
- Фоллбек: `qwen2.5-coder-32b` для задач кодирования
- Маршрутизация: `ModelRegistry.route_task("evolution", project=N)`

### 3.2 Filter Overlord (`filter_overlord.py`)
**Назначение:** Пост-эволюционная верификация — классификация проектов как FROZEN, READY или ARCHIVED.

**Протокол (Строгий Режим):**

| Классификация | Критерий | Результат |
|---------------|----------|-----------|
| **FROZEN** | Суммари существует + покрытие ≥95% + строк кода >100 + нет незакоммиченных изменений | Идеальный код, никогда не трогать |
| **READY** | Суммари существует + покрытие ≥80% + строк кода >50 | Готов к деплою |
| **ARCHIVED** | Нет суммари, покрытие <80% или не соответствует выше | Мертвый/сломанный — архивировать |

**Верификация READY включает:**
- Полный повторный запуск pytest с покрытием
- Сканирование безопасности (bandit)
- Проверка на TODO/FIXME в продакшн-коде
- Понижение до ARCHIVED при любой неудаче

### 3.3 Model Registry (`model_registry.py`)
**Назначение:** Интеллектуальная маршрутизация моделей с проверкой здоровья, failover и ротацией ключей.

**Особенности:**
- 8 узлов вывода (локальные + облачные)
- Персональные предпочтения моделей на проект
- Мониторинг здоровья с circuit breaker
- Интеграция с ротацией ключей (NVIDIA, OpenCode и др.)
- Логирование решений маршрутизации для аудита

### 3.4 Поддерживающие Системы
- **Encrypted Comms** — зашифрованная межагентная связь
- **Pulse Watchdog** — мониторинг здоровья узлов
- **Professor Sync** — дистилляция знаний между циклами
- **Textbook Learning** — автообучение из документации
- **Vault Git Sync** — двусторонняя синхронизация с хранилищем
- **Holy Code Deploy** — деплой баннеров/компонентов
- **DJ Studio** — генерация радио/музыки
- **Cycle Start** — оркестрация 4-часовых циклов
- **Model Registry Health** — проверки здоровья узлов

## 9. Образовательная Ценность и Инсайты

### Что Делает Living Code Protocol Уникальным:
1. **Автономная эволюция кода** — человек задает только направление, остальное делает система
2. **Строгие качественные ворота** — никакого "готового" без реальной проверки
3. **Архитектура замораживания** — идеальный код становится неприкосновенным артефактом
4. **Многоуровневая верификация** — от подциклов до супер-супервизора
5. **Интеллектуальная маршрутизация моделей** — оптимизация использования LLM ресурсов
6. **Экосистемный подход** — разные типы проектов получают разные модели и ресурсы

### Уроки для Разработки:
- **Честность перед хвастовством** — лучше "фасад рабочий, ядро пустое" чем ложные RC метки
- **Видимый прогресс каждый цикл** — нет места симуляции завершения
- **Нулевое ручное вмешательство** — система должна работать автономно
- **Консультация перед крупными изменениями** — особенно при работе с критическими компонентами
- **Ревью кода на локальном LLM** — использование llama.cpp для проверки изменений
- **Запрет на фейковую функциональность** — глобальный бан на симуляции без реального кода

### Философия в Действии:
> **"Код, который не слышал курилку — сам не знает. Код, который слышал — боится, но работает."**

Это означает:
- Все изменения должны быть документированы в Kurilka journal
- Перед работой нужно понимать контекст и историю
- Страх перед изменением приводит к более тщательной проверке
- Но最终 код все равно должен работать в реальных условиях

## 11. Заключение
Living Code Protocol представляет собой передовый подход к автономной разработке ПО, где эволюция, качество и архивация объединены в единую самоподдерживающуюся систему. Протокол уже ~85% реализован и демонстрирует устойчивую работу в режиме 4-часовых циклов.

После устранения выявленных пробелов (портируемость путей, недостающие обертки, Супер-Супервизор и миграция CompleteProjects) протокол достигнет полной автономности с возможностью:
- 4 проекта × 10 подциклов × 6 циклов/день = 240 шагов эволюции в день
- Автоматическое обеспечение качества на каждом этапе
- Самоarchiving мертвого кода и сохранение идеального
- Непрерывное обучение и адаптация через Professor Sync и Textbook Learning

Это не просто инструмент разработки — это новая парадигма взаимодействия человека и ИИ в создании программного обеспечения, где человек устанавливает цели и границы, а система autonomously эволюционирует к лучшим решениям через проверенные циклы спора, проверки и замораживания.
