## Главные факты, которые стоят внимания Машины Кода

**1. Найден блокер: Vulkan/RADV не видит GPU без группы `render`.**
`vulkaninfo --summary` из агентского контекста показывает **llvmpipe** — софтверный растеризатор,
то есть любой GPU-бенчмарк молча уезжает на CPU. RADV падает: `Could not open device
/dev/dri/renderD128: Permission denied`. `thomas` есть в `/etc/group` в группе `render`, но не в
текущей сессии; ACL на `/dev/dri/*` не выданы. Рабочий обход проверен живьём: `sg render -c "…"`
→ `AMD Radeon 780M Graphics (RADV PHOENIX)`, Mesa 26.0.8, Vulkan API 1.4.335.
Рекомендация: `setfacl -m u:thomas:rw /dev/dri/renderD128 /dev/dri/card1` + `SupplementaryGroups=render`
в юнитах llama-server/clef.

**2. Поправка факта: первоисточник ZINC был указан неверно.**
Заметка ссылалась на `zinc-org/zinc` — это пустая заглушка (size 0, ★0, ни одного коммита,
`pushed_at` = `created_at`). Настоящий проект — `zolotukhin/zinc`: ★518, MIT, Zig, push
2026-10-04T03:42, 6 issue, релизов нет.

**3. RSI-Harness — два инварианта, защищённых тестами.**
(а) без `--genome` бинарь ведёт себя ровно как `pi`; (б) `pi-surface.test.ts` краснеет, когда
обновление Pi добавляет непрошитый ключ конфигурации. Конфигурация — патч, а не замена:
необъявленное поле наследует дефолт, `null` — явный сброс. И формулировка RSI, которой не хватало
нашим заметкам: **модель правит свой харнесс, а не веса** — теми же средствами, которыми харнесс
пишут руками.

**4. Границы RSIH, названные честно.** Удалённой установки одной командой нет. **Гейта
редактирования перед публикацией нет** — сам проект признаёт, что Genome, выжимаемый из приватных
транскриптов, должен бы ловить абсолютные пути, intranet-домены и секреты, но не умеет. В репозитории
**нет ни бенчмарка, ни кода обучения/оценки** — «+X % качества» ждать нельзя.
