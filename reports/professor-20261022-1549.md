### 3. SWE-Gate — Laya **1.3456** (1.2+ → первый приоритет)
**Конспект:** `knowledge-base/SWE-Gate-функциональные-тесты-не-достаточны.md`
**Суть:** Бенчмарк (arXiv:2609.04167, 303 инстанса, 75 Python-репо) разделяет **functional test** («работает?») и **constraint test** («приемлемо для ревьюера?»). **34.3% патчей (221/644)** прошли functional но провалили constraint — hidden failures.
**Применимость:** Прямой сигнал для наших UI-гейтов / merge-гейтов: нужен **два набора тестов**. Правило для Аудитора: «тесты зелёные» от кодера — заявление; отчёт прогона обоих наборов — доказательство. Связь с A²E-аудитом и kode:harness.

## Правила, добавленные к протоколу (не логи)
1. **Память без доказательной базы — эхо, а не память** (из mnem/Sentry). Факт должен уметь показать, из какого прогона взят.
2. **Два набора тестов для гейтов** (из SWE-Gate): functional + constraint. Hidden failures = 34%.
3. **Судья выбора — отдельный слой, а не харнесс** (из strands-decider/jeff). Рою нужна точка выбора из N вариантов.
4. **Venv не смешивать никогда** — проверка версии через импорт, не лог установки (strands-decider vs gptswarm transformers 5.18 vs 4.44).
5. **Трёхслойный поиск** (из jevgrep/claude-mem): индекс (50-100 токенов) → timeline → полные детали только для отфильтрованных ID (~10× экономия токенов).
