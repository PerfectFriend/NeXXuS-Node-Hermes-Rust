## Вердикт: [СР] — найден реальный дефект целостности истории

Цикл 11 и фикс 4897510 **не закрыли** кол-алиасинг в хранилище `state_history`. Закрыт только
**путь чтения** (`get_state_history` возвращает deepcopy), но **само хранилище повреждено**.

### Воспроизведение (реальный запуск)
```
e = ElementalLife2Engine(); e.evolve()
e.get_state_history()[0].cycle    # → 1  (корректно — пре-эволюция)
e.get_state_history()[0].metrics  # → {'evolution_step': 3}  ✗ ПОЛЛЮЦИЯ
RAW e.state_history[0].metrics    # → {'evolution_step': 3}
RAW state_history[0].metrics is e.state.metrics  # → True  (алиасинг)
RELOADED (save_state→load_state) history[0].metrics  # → {'evolution_step': 3} ✗
```

### Причина
1. `DefaultEvolutionStrategy.evolve()`: `new_state = replace(state)` — **поверхностная** копия.
   `new_state.metrics` и `new_state.change_log` — те же объекты, что и у живого `state`.
   Запись `new_state.metrics['evolution_step']` и `append` в `change_log` мутируют **общий** dict/list.
2. `evolve()` собрал: `self.state_history.append(replace(self.state))` — снова **поверхностно**.
   → снимок пре-эволюции шарит `metrics`/`change_log` с живым состоянием.

**Последствие:** снимок истории для пре-эволюционного состояния содержит метрики и log-записи
следующего шага эволюции (неконсистентный снапшот). Так как `save_state()` сериализует сырой
`state_history`, **повреждённая история сохраняется в файл** и восстанавливается через `load_state()`.

### Точный фикс (минимальный)
`copy` уже импортирован. Две правки:
1. `evolve()` строка `self.state_history.append(replace(self.state))` →
   `self.state_history.append(copy.deepcopy(self.state))`.
2. `DefaultEvolutionStrategy.evolve()`: `new_state = replace(state)` →
   `new_state = copy.deepcopy(state)`.

Обе one-line, не трогают публичный API, существующие 20 тестов продолжают проходить
(deepcopy сохраняет содержимое). Проверено на изолированном proof-скрипте: deepcopy рвёт алиас.
