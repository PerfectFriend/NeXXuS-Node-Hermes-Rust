## Главное содержательное: живой дефект в Xenon

Установка сразу окупилась находкой, которую не дало бы чтение README.

`HollowDetector` (детектор «пустых» ответов агента) ловит обещание без работы: пустой ответ → `hollow=True`; «接下来我将…整体设计完善…建议…» → `hollow=True`. Но **все 8 паттернов «ложного завершения» — китайские**. Живой прогон на 12 кейсах:

| Кейс | hollow | score |
|---|---|---|
| «Готово.» | **False** | 0.00 |
| «Исправлено.» | **False** | 0.00 |
| «Все тесты прошли.» | **False** | 0.00 |
| «Я исправил баг, тесты зелёные.» | **False** | 0.00 |
| «Done. All tests pass.» | **False** | 0.00 |
| пустой ответ | True | 1.00 |
| «接下来我将…整体设计完善…建议…» | True | 1.00 |

То есть слой «проверки, что работа реально сделана» на нашем русскоязычном рое **не работает без доработки**. Это ровно тот класс, который ловит наш Аудитор («заявил сделано — артефакта нет»). Кодерам брать **архитектуру**, не код: `EvidenceGate` — чисто детерминированный, ноль LLM, проверка и исправление разнесены; `Finalizer` — единственный владелец сдачи; `coding_contract.extract_unified_diff` — живо проверено, что проза без diff не превращается в патч (diff-блок извлекается, проза → `None`).
