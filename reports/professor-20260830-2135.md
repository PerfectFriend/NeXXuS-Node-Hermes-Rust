## Изученные темы

### 1. PocketFlow — 100-line LLM framework 🟢
- **Источник:** github.com/The-Pocket/PocketFlow (11.1k★, MIT, 641 коммит) + прочитан реальный исходник `pocketflow/__init__.py`.
- **Ядро:** единственная абстракция — **Graph**. Узел = `prep → exec → post`, рёбра = именованные переходы по action (`node - "action" >> next`). Retry через `max_retries+wait`, Batch/Async/Parallel — вариации. Flow копирует узлы каждый шаг (`copy.copy`), состояние только в `shared` dict.
- **Сравнение:** 100 строк / +56KB против LangChain 405K строк/+166MB, CrewAI 18K/+173MB, LangGraph 37K/+51MB.
- **Применимо:** Living Code — замена ad-hoc Producer/Auditor/Lord-скриптов на Flow; GodModePolyBot — research-loop как Flow; SuperGuard bot FSM. Философия "humans design, agents code" резонирует с Living Code.

### 2. Strands Agents SDK 🟢
- **Источник:** github.com/strands-agents/harness-sdk (7.0k★, Apache-2.0, 2537 коммитов) + strandsagents.com.
- **Суть:** production agent harness из внутренних систем Amazon. Монорепо: strands-py + strands-ts + strands-mcp + site + governance. Default Bedrock, но провайдеры взаимозаменяемы (Anthropic/OpenAI/Gemini/Ollama).
- **Фичи:** context management, execution limits, OpenTelemetry, Zod-typed tools, multi-agent patterns, MCP-сервер (`uvx strands-agents-mcp-server`) — может стать tool'ом внутри нашего Hermes.
- **Вердикт:** держать в радаре; не тащить сейчас (AWS-bias, тяжёлый dep-graph). Вернуться когда Living Code потребует observability/multi-agent.

### 3. OpenClaw 🟢
- **Источник:** github.com/openclaw/openclaw (OpenClaw Foundation, pnpm/TS-monorepo).
- **Архитектура:** Gateway (local control plane: sessions/tools/events/cron/webhooks) + Control UI/CLI/TUI + Channels (WhatsApp, Telegram, Slack, Discord, Google Chat, Signal, iMessage, Teams, Matrix, IRC, Feishu, LINE, Mattermost, Nextcloud Talk, Nostr, Synology, Tlon, Twitch, Zalo, WebChat) + companion nodes (macOS menu bar, iOS/Android voice/canvas/camera).
- **Безопасность (ключевое):** default `dmPolicy="pairing"` на всех DM-каналах — незнакомый отправитель получает pairing code, его сообщение не обрабатывается. Security/exposure/sandboxing гайды в комплекте.
- **Multi-agent routing:** каналы/аккаунты/peers → изолированные агенты (workspaces + per-agent sessions). plugins через Plugin SDK + ClawHub, skills как у Hermes.
- **Вердикт:** не переписывать наш стек, но это **референс-архитектура** для multi-channel gateway. Немедленно применимы паттерны: DM pairing и cron/sessions как first-class citizens.
