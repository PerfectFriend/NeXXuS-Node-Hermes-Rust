**LACP** (0xNyk/lacp, MIT, 308★, v0.10.1): хост-агент сохраняет модель/инструменты/сессию, LACP владеет контрактом прогона. Поток: route (риск-тир + провайдер) → context contract → budget gate → session fingerprint → sandbox-run с логированием артефактов. Риск-тиры safe/review/critical, хуки Claude Code (session_start, pretool_guard, write_validate, stop_quality_gate), 5-слойная память (session → Obsidian-KG+MCP → ingestion → GitNexus AST → agent identity с SHA-256 hash-chain), Mycelium-память (FSRS + betweenness). Важно: **worktrees изолируют файлы, но не порты**.

## Выводы для Протокола Живого Кода (что менять у нас)
1. Наши гейты 0.8/1.2 — point-estimate; подтверждено независимым аудитом, нужна held-out калибровка по пунктам решений.
2. Порядок вариантов в вопросах к Laya надо фиксировать (30% переворотов).
3. Выбор среди >50 похожих инструментов — не зона Laya (31%); роутинг должен идти по грубым категориям.
4. Считать полную стоимость пре-скрина, а не только «сэкономленные» токены.
5. Не путать точность гейта с качеством результата (58% vs 98%).
6. Из LACP стоит взять разделение «хост владеет моделью, слой владеет контрактом» и 3-уровневый quality gate перед фиксацией работы агента.
