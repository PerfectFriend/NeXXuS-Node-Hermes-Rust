## Что конкретно взято (польза для Машины Кода)

**1. AGP — протокол, под который наш цикл уже наполовину написан.** Два слоя: RSPL (промпты/агенты/инструменты/окружения/память как версионированные ресурсы + model/version/dynamic/trace менеджеры) и SEPL (reflect → select → improve → evaluate → commit с откатом). Наш «Искатель → Профессор → UI-гейт» — это грубый reflection optimizer без commit-дисциплины. Прямо применимо: коммит = версионный переход с возможностью отката, а не «запись в журнал».
Ключевые цифры: PS-Joint-Evo бьёт одиночные стратегии (gpt-4.1 на AIME24: Prompt-Evo 33.3%, Solution-Evo 36.7%, совместная 40.0%); выигрыш тем больше, чем слабее модель (+71.4% у gpt-4.1); GAIA Level 3 +33.3% против Level 1 +8.2%. Честное ограничение из статьи: эволюция памяти и окружения реализована, но как абляция не оценена; возможен дрейф поведения при плохо заданных целях.

**2. Harness-Aware Evaluation — рамка, которая показывает, чего не хватает в наших отчётах.** Четыре фактора M/H/E/V + протокол P, формула ΔH = SB(M,H₂,E,V;P) − SB(M,H₁,E,V;P). Отдельно полезное: «падение сервиса — событие окружения, повтор запроса — решение харнесса». Для воспроизводимости самоэволюции надо отчитывать **пространство допустимых модификаций, сигнал обратной связи, частоту обновлений и итоговый конфиг** — ровно то, чего нет в нашем протоколе сейчас.

**3. EDDI — паттерн «один декларативный артефакт вместо кода» для наших стадий крона.** Проверено по README: Java 25 + Quarkus, 20 000+ тестов, покрытие >90% instr / >80% branch, один порт 7070, MCP+A2A нативно. Полезные мелочи: `eddi update` тянет образ по remote digest; compose-файлы берутся из тега последнего релиза, **не из main**; миграции 6.4 ломают дефолты (fail-closed) — у нас нужен свой чек-лист апгрейдов. **Тяжёлый стек — не ставим** (по правилу Учебника), берём только паттерн.

**4. AMD ROCm guide — команды для нашей 780M подтверждены официально.** `GGML_HIP=ON -DAMDGPU_TARGETS=gfx1100` (RDNA 3), `-DGGML_OPENMP=OFF` при ошибках линковки OpenMP, `HIP_VISIBLE_DEVICES` на multi-GPU, `n_gpu_layers=-1` и `n_ctx` 4096–8192 для iGPU. Единый GGUF-путь для Lemonade/LM Studio/Ollama/llama.cpp.
