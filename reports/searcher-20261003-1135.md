## Задача 2. Gambit не видит локальных моделей — ЗАКРЫТА БЕЗ УСТАНОВКИ OLLAMA

**Было.** Провайдер `ollama` в Gambit 0.8.6 проверяет сервер через `GET /api/tags`.
llama-server отдаёт только `/v1/*`, `/api/tags` → 404 → Gambit не видел ни одной модели:

```
OLLAMA_BASE_URL=http://127.0.0.1:8792/v1 gambit run ...
  → Failed to list Ollama models (404 Not Found)
```

Прошлый слот запросил у Владыки аппрув на установку настоящего Ollama, считая это
единственным выходом. **Оборачивать не пришлось.**

**Стало.** `/home/thomas/LivingCode/tools/ollama_shim.py` — ~200 строк на stdlib,
переводит Ollama-протокол на `/v1` llama-server. Ни Ollama, ни API-ключ, ни снятия
ограничений безопасности.

```bash
~/LivingCode/tools/ollama-shim-gambit.sh start          # служба, идемпотентно
export OLLAMA_BASE_URL=http://127.0.0.1:11434
export OLLAMA_API_KEY=local     # НЕ секрет: Gambit проверяет только непустоту
cd ~/LivingCode/vendors/gambit/gambit
../gambit-linux-x64 run hello.deck.md --model-force 'ollama/Cloudflare_clef-flash-Q4_K_M.gguf'
```

**Живое доказательство (два разных deck'а, плюс проверка через службу):**

| deck | модель | вывод | код |
|---|---|---|---|
| `hello.deck.md` | clef-Q4 (8792) | `What is your name?` | 0 |
| `hello.test.deck.md` | Qwen3.5-9B (8081) | `Gambit` | 0 |

**Выбор upstream — честно, с оговоркой.** По умолчанию в скрипте стоит clef (:8792):
быстрый, проходит простой deck. Qwen3.5-9B (:8081) — единственная из двух, умеющая
tool-calling, и она проходит deck с инструментами; но холодный старт 9B не укладывается
во внутренний таймаут Gambit (`Timeout exceeded` даже на простом deck, проверено дважды).
Выбрать явно:

```bash
OLLAMA_SHIM_UPSTREAM=http://127.0.0.1:8081 ~/LivingCode/tools/ollama-shim-gambit.sh start
```

**Четыре грабли, каждая стоила итерации:**
1. **Алиасы без слэшей.** Gambit разбирает `provider/model`, а `/v1/models` отдаёт полный
   путь `/home/.../clef-flash.gguf` → `ollama/Cloudflare_clef...` не находился. Shim отдаёт
   basename и сам подставляет полный путь при обращении к upstream.
2. **Пост идёт на `/responses`, не `/v1/responses`** — Gambit срезает префикс базы.
3. **Первый ход = ТОЛЬКО system-сообщение**, вход приходит отдельным tool-вызовом
   `gambit_context`. Chat-шаблон clef падает с `No user query found in messages`; shim
   добавляет пустой user-оборот, если его нет.
4. **Tool-calling обязателен.** clef-Q4 на deck с инструментами даёт пустой ответ при
   **exit 0** — тихий бесполезный прогон.

**Служебный запуск вместо ручного.** Первый вариант поднимал shim в сеансе — процесс
умирал вместе с ним, и следы (пустой лог, мёртвый pid) выглядели как поломка. Скрипт
`ollama-shim-gambit.sh` делает `setsid` + `disown`, идемпотентный `start` и health-check до
возврата. Проверено: `stop` → `start` → `status`, и Gambit после этого отвечает при
работающей службе, а не только вручную.

**Честные ограничения (не работает):**
- `stream: true` не поддержан — для `gambit run` хватает, для REPL с живым выводом нет;
- `size`/`digest` в листинге — заглушки (Gambit не сверяет, но в выводе они были бы
  неверными);
- `gambit grade --state <file>` требует `workspace.sqlite` рядом с состоянием, JSON-путь
  не подходит — это формат usage, не поломка.

### Урок слота, который стоит дороже любой находки

**`exit 0` не доказывает полезность.** clef отдал пустой ответ при exit 0 на deck с
инструментами — и в отчёте агента это выглядело бы как «прогон успешен». Ровно тот же
класс дефекта, что ложно-зелёный отчёт из задачи 1, только в другом месте: инструмент,
который должен проверять работу, сам выдаёт зелёный свет на пустом результате.
Проверять надо содержание ответа, а не только код возврата.
