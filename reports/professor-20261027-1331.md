## Главное для Машины Кода

1. **QM дал шкалу изоляции для роя кодеров:** scope = своя память/файлы/ключи/права/кроны/песочница; шаринг только явным грантом. Три security-posture (Strict — каждый вызов инструмента на одобрении; Auto — блок приватной сети; Dangerous — без гейтов), которые узкий scope может только ужесточать. Плюс `execute` в долговременной песочнице и Postgres как обязательный слой долговременности.
2. **Одобрение надо привязывать к конкретному вызову** (OWASP LLM06:2025): совпадение с pending-вызовом по точным аргументам, аутентифицированный человек, одноразовость. Наш экран одобрения должен показывать сырой вызов, а не пересказ агента. Гейт — по последствиям, а не по привычке (MITRE ATLAS AML.M0029).
3. **Три-статный контракт разрешений** allow / deny / **no_egress** с монотонным распространением на потомков — то, чего у нас нет: действие разрешено локально, сеть запрещена.
4. **Aletheia меняет вопрос тестирования правил:** не «правильный ли патч», а «какие полномочия реально понадобились» (свидетельство dispensability). Готовая рамка для регрессионного теста наших правил/скиллов.
5. **rdna-boosts — патчи, а не форк:** 15 линейных `git am`-патчей поверх ванильного llama.cpp, всё по умолчанию, `release.json` как источник истины, `ENVIRONMENT.md` с классификацией переменных (kill-switch/opt-in/tuning/diagnostic). **Наш gfx1100 (RX 7800M) — прямой target**, fused MoE MMQ и WMMA FA на нём валидированы авторами.
6. **Индекс локальных LLM пересчитал скорость для MoE:** малые MoE (≤40B) декодируют в 2–4 раза быстрее прежней плоской оценки (Qwen 3.6-35B-A3B: 64 tok/s на M6 против оценки 14). Для нашего стенда — аргумент в пользу MoE.
