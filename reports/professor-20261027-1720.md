## Что конкретно в конспектах (суть)

**1. KAOS (canivel/kaos, Python 3.11+, MIT, DOI 10.5281/zenodo.21533588, v2.1.0, push 2026-09-06, 9★, 24 открытых issue).** Каждый агент работает в изолированной песочнице внутри одного файла SQLite; каждое действие пишется в журнал — аудит агента это SQL-запрос (`SELECT * FROM tool_calls WHERE agent_id = ?`). Замеры автора: 2 000 агентов × 25 воспоминаний = 50 000 записей за 1,1 с, кросс-агентный поиск FTS5/BM25 — p95 15,0 мс на 20 прогонах. Память само-тюнится (usage-weighted ранжирование). **Главная идея — kill gates:** для каждого механизма-кандидата гейты пишутся и лочатся по sha256 **до** написания кода фичи, есть self-test фальсификации, доказывающий, что фича может проиграть, вердикт ACCEPT/REJECT/VOID обязателен; 15 кандидатов оценено с v0.7, ноль выпущено «на надежде», каждый вердикт с audit trail лежит на диске. GEPA-роутер — классификатор сложности + таблица маршрутизации с retry/fallback и потолками wall-clock (это **не** генетический Pareto-алгоритм промптов); под капотом сырой `httpx`, без OpenAI SDK и без LiteLLM. Экстра-пакеты: `[router] [mcp] [agent-sdk] [ui] [all]`, MCP-сервер на 58 инструментов, плагины через entry-point `kaos.plugins`, встраивается в Claude Code как плагин (`claude plugin marketplace add canivel/kaos`). **URL в Учебнике был `kaos-ai/kaos` → GitHub API 404; настоящий владелец `canivel/kaos`, URL исправлен.**

**2. intel/ipex-llm (8 844★, Apache-2.0, push 2026-01-28, archived=true).** Первая строка README: «THIS PROJECT IS ARCHIVED» — Intel не гарантирует development/support, **патчи не принимаются**, и «проект имеет известные проблемы безопасности». Исторически: ускорение LLM на Intel GPU/NPU/CPU, 70+ верифицированных моделей, FP8/FP6/FP4/INT4, FlashMoE (DeepSeek V3/R1 671B и Qwen3MoE 235B на 1–2 Arc GPU), portable-zip для llama.cpp/Ollama, self-speculative decoding (~30 % латентности FP16/BF16), QLoRA LLaMA2-70B за 3,14 часа на 8 Intel Max 1550. Отдельное предупреждение: `mmap`-загрузка в llama.cpp **может утекать данные через side-channels** в мультиарендной/shared-host среде — лечится `--no-mmap`.

**3. A2A SDK v1.0 (Python 2 220★ / JS 647★ / Go 495★, все три push 2026-10-27).** Все три перешли на спецификацию v1.0.0 и держат **совместимость с v0.3 как явный opt-in слой**. Матрица одинакова: v1.0 и v0.3 (compat) — client и server по JSON-RPC, HTTP+JSON/REST и gRPC; **ключевое изменение v1.0 — gRPC как полноправный транспорт**. Python: Python 3.10+, extras `[fastapi] [grpc] [telemetry] [encryption] [postgresql|mysql|sqlite]`, персистентность задач и push-уведомлений в SQL, проверка через `a2a-inspector`. JS: один пакет `@a2a-js/sdk`, три транспорта на едином `DefaultRequestHandler`, gRPC только для Node, сторы PostgreSQL/MySQL/SQLite/Cloudflare D1 через Kysely, миграции CLI `a2a-db`. Go: **требует Go 1.26.0+**, пакеты `a2asrv`/`a2aclient`, транспорт-независимый handler, резолв AgentCard через `agentcard.DefaultResolver.Resolve`, версия спецификации экспортируется как `a2a.Version` (версия SDK ≠ версия спеки).

**4. tigerless-labs/agent-memory (4 737★, MIT, v0.1.0, push 2026-10-26, 24 открытых issue).** Markdown-файлы — единственный источник истины, SQLite-индекс рядом — пересобираемый кэш (`rm -rf .index/ && mem rebuild` теряет ноль знаний, закреплено тестом). **Recall отдаёт путь, а не текст:** L0 (абстракция + путь + якорь + score), дальше агент сам выбирает глубину `mem read --level outline|abstract|full`.
