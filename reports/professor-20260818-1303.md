# Отчёт Профессора: Изучение Spec-Driven Development с GitHub Spec Kit

**Дата:** 2026-08-18  
**Источник:** textbook/Spec-Driven-Development-Spec-Kit.md

## 🎯 Core Concept
Спецификации становятся исполняемыми — непосредственно генерируют рабочие реализации, а не просто направляют их.  
Код служит спецификациям (а не наоборот).

## 🏛️ The Constitution (9 Principles)
1. **Library-First Principle** — Каждая функция начинается как автономная библиотека.
2. **CLI Interface Mandate** — Все библиотеки предоставляют функциональность через CLI (stdin/stdout, JSON).
3. **Test-First Imperative** — НЕТ кода до тестов (обязательное TDD).
4. **Project-Defined** — Стандарты интеграционного тестирования.
5. **Project-Defined** — Требования наблюдаемости.
6. **Project-Defined** — Версионирование/разрушающие изменения.
7. **Simplicity** — Максимум 3 проекта, нет будущего-защиты.
8. **Anti-Abstraction** — Используйте фреймворк напрямую, одна модель представления.
9. **Integration-First Testing** — Реальные базы данных, настоящие сервисы, контрактные тесты обязательны.

## 🔧 Specify CLI Features
- **Extensions** — Добавляют возможности (Jira, код-ревью, V-Model прослеживаемость).
- **Presets** — Настраивают без добавления возможностей (соответствие, Agile, безопасность).
- **Bundles** — Наборы на основе ролей (PM, BA, Security, Developer).
- **Templates** — Ограничивают поведение LLM для качества.

## 📋 7-Step SDD Workflow
```bash
# 1. Install
uv tool install specify-cli --from git+https://github.com/github/spec-kit.git@v0.14.4

# 2. Initialize
specify init my-project --integration copilot

# 3. Constitution
/speckit.constitution "Project governing principles..."

# 4. Spec (WHAT/WHY)
/speckit.specify "Feature description..."

# 5. Plan (HOW - tech stack)
/speckit.plan "Go + gRPC + YOLOv11n + ONNX DirectML..."

# 6. Tasks
/speckit.tasks

# 7. Implement
/speckit.implement
```
