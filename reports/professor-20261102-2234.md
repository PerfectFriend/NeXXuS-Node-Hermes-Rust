## Ключевые инсайты для Living Code

### 1. **L3 Independent Critic — критический пробел**
Все изученные работы (Self-Evolving Harness, Rethinking Verification, RRSI, RuHarness) сходятся: **нужен отдельный критик со свежим контекстом**, который:
- Получает только `(task_spec, deliverable, acceptance_criteria)` — НЕ траекторию
- Может запускать throwaway пробы под `/tmp`
- Даёт evidence-based вердикт, а не «вроде бы ок»

**Наш Аудитор делит контекст с Кодером → это L2, не L3.**

### 2. **Phantom Guardrails — реальная угроза для нашего add-only цикла**
Самоулучшающиеся харнессы галлюцинируют несуществующие проблемы и добавляют «призрачные гейты».
- Наш цикл Professor→Coder→Auditor **только накапливает** навыки/гейты (нет удаления)
- **Evidence Gate не проверяет: «Был ли реальный провал?»**
- Нужен: Counterfactual Fabrication Lab, механизм удаления, валидация провала перед фиксом

### 3. **Регуляризация эволюции — отсутствует**
RRSI показывает: без **annealed edit budget**, **critic+pruner**, **evidence-aware credit** эволюция переобучается под текущие бенчмарки.
- У нас: никакого бюджета правок, никакого критика, никакой отсечки устаревших изменений
- Нужно: бюджет тем на слот (косинус: 5→4→3→2→1), трекер опровергнутых гипотез, Pruner

### 4. **Коэволюция рубрик — наш Evidence Gate статичен**
RuHarness: рубрики эволюционируют вместе с харнессом (probation→active→dormant→retired, outcome-blind judge).
- Наш Evidence Gate: фиксированные правила («тесты зелёные», «нет фейков») — **не пересматриваются**
- Нужно: динамический пул критериев, пересчёт relevance каждый раунд, валидационный набор

### 5. **Multi-benchmark evaluation — единственный способ измерить generalization**
Все работы: held-out + OOD benchmarks (5–8 штук, никогда не используемые в эволюции).
- У нас: оценка только по текущим задачам слота
- Нужно: поддерживать OOD тест-сьюту (coding, retrieval, reasoning, dialogue, agentic)

### 6. **Git worktrees + heterogeneous workers = паттерн ultraswarm**
Лёгкая изоляция через Git worktrees, разные CLIs/модели под разные роли, effort escalation перед tier escalation.
- Наши cron-агенты: могут использовать worktrees, разные модели через Hermes multi-bot
