### `alarm_sting.wav` — стинг срабатывания тревоги

Пять слоёв:
- шумовой транзиент 120 мс (HP 2 кГц) как «удар по металлу»
- FM-удар с несущей 880 Гц и экспоненциальным глиссандо вниз до 180 Гц (индекс 9.0, отношение 1.41 — некруговое отношение даёт металлический, а не «колокольный» тембр)
- кластер 5 расстроенных пил ±42 цента под ФНЧ 5.2 кГц (диссонирующее «цифровое сиреновое» облако)
- суб-удар 55 Гц (вес тревоги на маленьких динамиках)
- пульс 440 Гц раз в секунду.

Динамика по RMS-децимам: **−8.4 → −11.2 → −14.6 … → −31.6 dBFS**. Время атаки **31.8 мс** — тревога считывается мгновенно. Финальные 60 мс срезаны в ноль: «удар и тишина».

### `boot_chime.wav` — шимпер запуска сервиса

Восходящее арпеджио на FM-колокольчике: F#3 (185 Гц) → F#4 (370 Гц) → B4 (494 Гц) → F#5 (740 Гц), старт каждой ноты со сдвигом 0.11 с. У каждой ноты второй голос с расстройкой +0.3 % — из-за него тембр слегка «цифровой». Мажорная терция в верхней части арпедии (F#–B) даёт требуемую «уверенность» — в отличие от тревоги, где диссонирующая терция использовалась намеренно.

Подложка — тихий пэд на F#2 (92.5 Гц) под ФНЧ 900 Гц, входит на 0.25 с: без него трек звучал бы «пустым звонком». Динамика: **−9.0 → −10.3 → −13.7 … → −67.7 dBFS**, колокольный спад с длинным хвостом; ноты перекрываются, а не перечисляются.

### `ambient_loop.wav` — фоновый эмбиент панели мониторинга

Четыре слоя:
- суб-дрон 55.02 Гц + октава 110.03 Гц (амплитуда «дышит» ±18 %)
- средний пад — супер-пила 5 голосов ±16 центов под медленно «дышащим» ФНЧ ( свип 380 ± 260 Гц, период 31.5 с)
- верхний «шелест» — розовый шум ФНЧ 1.4 кГц / HP 300 Гц, ±30 %
- три одиночных системных пульса 880 Гц на 2.0 / 9.5 / 17.0 с.

**Бесшовность построена, а не обещана.** L = 31.5 с исходника; `fold = S[L−xf:L]·fade_down + S[0:xf]·fade_up`, `body = S[xf:L−xf]`, `y = fold ++ body` → ровно 30.000 с. На стыке `y[−1] = S[L−xf−1]` и `y[0] = S[L−xf]` — **соседние отсчёты исходника**, разрыв равен одному шагу сигнала. Тоны подобраны с целым `f·L` (1733/L ≈ 55.02 Гц, 3466/L ≈ 110.03 Гц, 27720/L ≈ 880 Гц), огибающие периодичны ровно по L. Fade-in/out на файле не ставились — они бы стык порвали.

## 3. Приёмка

Контроль идёт **по сигналу, который реально лежит на диске**: файл записывается, читается обратно и анализируется заново, а не доверяются параметры до записи.

| Критерий | Порог | alarm_sting | boot_chime | ambient_loop |
|---|---|---|---|---|
| Клиппинг | < 0.1 % | 0 % ✓ | 0 % ✓ | 0 % ✓ |
| RMS | −45…−3 dBFS | −14.14 ✓ | −15.05 ✓ | −24.00 ✓ |
| DC offset | < 0.02 | 1.1e−5 ✓ | −1.6e−5 ✓ | −1.5e−5 ✓ |
| Мёртвые окна (20 мс) | < 35 % | 0 % ✓ | 0 % ✓ | 0 % ✓ |
| Спектральный центроид | > 90 Гц | 5241 ✓ | 2870 ✓ | 997 ✓ |
| Уникальность сигнала | > 0.05 | 0.891 ✓ | 0.742 ✓ | 0.198 ✓ |
| Вариативность сегментов | — | 0.500 ✓ | 0.806 ✓ | 0.119 ✓ |
| Разрыв на стыке лупа | ≤ 6 | — | — | **1.62** ✓ |
| Уровень у краев лупа | ≤ ±3 dB | — | — | **−1.66 dB** ✓ |

**Была итерация 2 — и это главное в отчёте.** Первая сборка лупа дала разрыв на стыке с отношением **12.66** при пороге 6 — стык был слышим. Причины: fade-in обнулял первые отсчёты, а огибательная ADSR с длинным release затухала в хвосте. Переделано: периодичные по L огибательные вместо ADSR, fold-back вместо «хвост в голову», фады на лупе убраны. После правки — 1.62 и разница уровней краёв 1.66 dB; RMS-огибающая по 12 равным частям ровная (−25.0 … −24.2 dBFS), провалов нет.

## 4. Движок: процедурный синтез — честное сравнение

Параллельно отработала **нейросетевая генерация** через MusicGen-small (`facebook/musicgen-small`, 587 млн параметров, CC-BY-NC). Beide engines отработали реально, результаты измерены одним анализатором.

| Трек | Процедурный | Разница, которая решила выбор |
|---|---|---|
| alarm_sting — **время атаки** | **31.8 мс** | MusicGen «выплывает» из тишины полсекунды: тревога не читается как событие |
| boot_chime — **время атаки** | **351.6 мс** | У MusicGen весь трек — разгон, пик на 2.95-й секунде из 3.94: колокольчик не «звонит», а «вырастает» |
| ambient_loop — **уровень краёв** | **−1.66 dB** | MusicGen затихает к концу на 77–82 dBFS: в цикле провал в тишину |
| Время генерации 3 треков | **1.8 с** | 188.9 с |
| Лицензия | своя реализация | CC-BY-NC (некоммерческая) — ограничение для коммерческого продукта |

**Отдельно про ложное «идеальное» совпадение.** У MusicGen-лупа `seam_ratio = 0.00` — по первому критерию это «идеально». Это **ложный PASS**: обе границы файла — тишина, поэтому |x[−1] − x[0]| = 0 тривиally. Второй критерий (уровень у краёв) вскрыл правду: +66.52 dB. Поэтому в приёмный контроль добавлен второй показатель `loop_seam_level_db`; без него MusicGen-луп прошёл бы приёмку и ушёл в продакшн с провалом.

**Причина отклонения MusicGen по существу:** модель обучена на музыкальных фрагментах и воспроизводит их структуру целиком — с нарастанием, а не с ударной атакой. `guidance_scale`, `top_k`, `top_p` управляют тембром и случайностью, но не структурой атаки. Для **событийных звуков интерфейса** (тревога, старт сервиса) это структурное несоответствие.

**В поставку ушли процедурные треки** — единственные, проходящие все критерии, соответствующие назначению каждого звука. MusicGen-версии сохранены как артефакты сравнения (`/home/thomas/.hermes/cache/scratch/mg_out2/`): если Продюсеру нужен нейросетевой тембр, их можно послушать — по текстуре они «живее» (центроид эмбиента 437 Гц против 997 Гц). Но как рабочие звуки они хуже, и несут лицензионное ограничение.

**Побочно найденный дефект MusicGen-пайплайна:** без `min_new_tokens` декодер выдаёт EOS досрочно и трек получается **втрое короче** заданного (2.94 с → 0.98 с). Также в скрипте ресемплинга был баг `gcd = 48000//8000 = 6`, из-за которого 32 кГц превращались в 16 кГц, а не в 48 кГц. Оба исправлены; в отчёт попали только уже исправленные результаты.
