## 1. Итог одной строкой

в сервисе** (Laya не поднялась после перезагрузки) и **заблокированный крон** (`LV-model-sync`).

## 3. Корневая причина: одна, а не пять

**Хронология (по журналу systemd, проверено):**

| Время | Событие | Источник |
|---|---|---|
| 23:18:04 | **Перезагрузка машины** (до неё — 10-часовая дыра, прошлый boot завершился 13:11) | `journalctl --list-boots` |
| 23:18:52–56 | Шлюз поднялся и **выстрелил все пропущенные слоты одной пачкой**: «catch-up after missed fire: scheduled 13:40, ran 23:18 (9h 38m late)» | `hermes cron list` |
| 23:20 | `кодер-project2` FAIL — **HTTP 429** после 3 попыток, пул моделей без альтернатив | отчёт FAIL |
| 23:34–35 | `кодер-project1/3/4`, `аудитор` FAIL — «Gateway disconnected», «Gateway draining: not_ready», «Interrupted during API call» | отчёты FAIL |
| **23:35:25** | **Шлюз убит OOM-killer'ом: `Failed with result 'oom-kill'`, 9,9 ГБ пик, 247 МБ swap** | `journalctl -u hermes-gateway` |
| 23:35:31 | Шлюз перезапущен (`restart counter is at 1`), все живые сессии агентов потеряны | systemd |
| 23:18–23:35 | В `cycle-52` уже было записано: «**laya: ✗ сервис недоступен (URLError)**» | `cycle-52-20261026-2318.md` |

**Механика:** `cron.max_parallel_jobs` был **не задан** (`null` = безлимит), а `cron.catch_up_missed: true`
разрешает запуск каждого пропущенного слота. После 10-часовой дыры это дало **10+ одновременных
агентов**, каждый с контекстом 64k+ токенов в одном процессе шлюза → 9,9 ГБ → OOM.

Это **не** проблема NVIDIA как таковая: прямая проба модели после восстановления отвечает за 7 с
(`ПИНГ` получен). 429 был **симптомом** перегрузки, а не болезнью провайдера.

## 4. Что сделано (исправлено)

### 4.1 Конфигурация — `cron.max_parallel_jobs`
```bash
hermes config set cron.max_parallel_jobs 3   # → config.yaml:98
```
Проверено по живому коду: `cron/scheduler_tick.py:168` → `_sched._resolve_max_parallel_workers()`
→ `cron/scheduler.py:4220` читает `cron.max_parallel_jobs` → `_get_parallel_pool(max_workers)`.
**Изменение подхватывается на следующем тике, рестарт шлюза не требуется.** Теперь гонка
catch-up запускает максимум 3 слота вместо 10+.

### 4.2 Сервис — `laya-warm` включён в автозапуск
Юнит был **`disabled`** — после перезагрузки он не поднимался, и цикл 52 писал «laya: ✗ сервис
недоступен (URLError)», то есть **все роли шли в локальный путь мимо внешнего судьи**.
```bash
systemctl --user enable laya-warm   # → enabled + active
```
Проверено: `http://127.0.0.1:8731/health` → `{"ok": true, "loaded": true, "rss_mb": 1680, …}`,
8 успешных вызовов Laya за этот сеанс (включая все 4 триажа выше).

### 4.3 Крон — `LV-model-sync` разблокирован
Ошибка: `Blocked: script path resolves outside the scripts directory (…/orchestration/scripts): 'sync_models.sh'`.
Причина — `sync_models.sh` был **симлинком** на `/home/thomas/LivingCode/scripts/sync_models.sh`,
а guard (`cron/scheduler_script.py:346-354`) проверяет `path.resolve()` — симлинк уводил за пределы
канонической папки. Заменён на **реальный файл** внутри `orchestration/scripts/` (содержимое
идентично, `bash -n` → SYNTAX OK, права `755`).

### 4.4 Knowledge-base — `studied` → `deployed`
Маркеров `[STUDIED]`/`[DEPLOYED]` в текстовой части Учебника нет (0 вхождений) — рабочая
конвенция проекта **эмодзи**: 🔴 не изучено / 🟡 в процессе / 🟢 изучено, а в графе знаний —
`status: "studied"`. Промотировано по **факту наличия конспекта на диске**, без выдумок:

  78 `studied` (без конспекта — честно оставлены), 22 без статуса, 1 `active` (не тронут).

## 6. Честные границы

- **Не чинил** приказ владельца о единственной модели: 429 лечится не добавлением второй модели,
  а снижением параллелизма (сделано) и решением оператора по квоте/фолбэку.
- **Не перезапускал шлюз** — правка `max_parallel_jobs` подхватывается на следующем тике,
  а рестарт сейчас снёс бы живые слоты (ровно то, что и было причиной отказа).
- **Не объявлял успехом то, что не проверил:** каждый фикс подтверждён реальным выводом
  (`hermes config get`, `systemctl is-enabled/is-active`, `curl /health`, повторный `json.load`
  графа с проверкой, что у всех 38 `deployed` узлов конспект существует на диске).
- **Промоушен ограничен фактом конспекта.** 78 узлов остались `studied` — у них нет изученного
  материала, и ставить им `deployed` значило бы выдумать знание. То же в Учебнике: 102 жёлтые
  строки, из них с конспектом 🟢 — одна (MASS).
- **Обе диспетчеризованные задачи (субагенты) умерли от того же 429**, который чинил, —
  их выводы в расчёт **не взяты**, всё выше проверено напрямую.
