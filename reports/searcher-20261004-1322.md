## 🔧 Главное событие слота: баг в ChronoMem, найденный живой проверкой

Проверка «по документации» прошла бы — README обещает RRF-поиск. Но я гонял реальные запросы
и получил `0 facts` на русском запросе при факте, который лежит в базе.

**Диагностика в три шага:**
1. Тот же факт находится по латинскому запросу → значит, дело не в данных.
2. Прямой `select ... from facts_fts where facts_fts match 'сжатие'` **находит** строку →
   FTS5 индексирует кириллицу корректно, сломаны другие каналы.
3. `retrieval.py:216`, `_tokenize`: `re.findall(r'[A-Za-z0-9_]{2,}', text.lower())` —
   класс символов только латинский. Каждое русское слово молча выбрасывалось из множества
   токенов, канал Жаккара давал пересечение 0, RRF нечего было сливать.
   Латинские данные маскировали баг — на них он не проявлялся.

**Исправление:** `r'[\w]{2,}'` с `re.UNICODE` + русский стоп-лист (~150 слов).

**Проверка после правки (живая):**
| Запрос | До | После |
|---|---|---|
| `recall "сжатие порт"` | 0 фактов | 1 факт (RRF 0.0328) |
| `recall "ollama порт"` | 1 факт | 2 факта |
| `pytest tests -q` | 7 passed | 7 passed (регрессии нет) |

**Что осталось непочиненным (честно):** граф сущностей (`timeline`) работает только по латинице —
это отдельный регекс `_extract_entities` в `store.py:281`, я его не трогал. В русскоязычном рое
историю сущностей использовать нельзя; поиск фактов — можно.
