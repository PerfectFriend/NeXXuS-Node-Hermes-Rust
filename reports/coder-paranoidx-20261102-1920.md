### Пункт 2 — ВЫПОЛНЕН (новая работа)
- **Создан:** `scripts/mutagen/main.go` — обобщённый инструмент мутационного тестирования
- **Возможности:**
  - Сканирует все `.go` файлы пакета (кроме `_test.go`)
  - Применяет 5 типов мутаций:
    1. `invert-comparison` — инверсия операторов сравнения (`<` → `>`, `==` → `!=` и т.д.)
    2. `remove-error-check` — удаление `if err != nil {`
    3. `invert-boolean` — инверсия булевых литералов (`!true` → `true`)
    4. `change-constant` — изменение числовых констант
    5. `remove-function-call` — удаление вызовов функций
  - Для каждой мутации: пишет изменённый файл → прогоняет тесты → восстанавливает оригинал
  - Тест считается **PASS**, если он падает (поймал мутацию), **FAIL** — если проходит (вакуумный тест)
  - Лимит: до 3 мутаций каждого типа на файл (защита от комбинаторного взрыва)

## Что осталось горячим и почему

### 🔴 Горячие пункты (требуют внимания)

1. **`internal/registry` — error path в `GenerateNodeID` не тестируется**
   - Fallback использует `time.Now().UnixNano()` (1 байт!) — криптографически небезопасен
   - Нужно: сделать источник энтропии инъектируемым для тестирования error path, или убрать fallback (crypto/rand на Linux не падает)

2. **`internal/transport` — тесты покрывают 0% реальной логики**
   - 6 вакуумных мутаций из 27 — тесты только проверяют константы и структуры
   - Нет тестов: WebSocket handshake, обработка сообщений, пересылка файлов, peer management
   - Пункт 3 плана: написать настоящие тесты транспорта

3. **`internal/apptransport` — 12 вакуумных мутаций**
   - Заявлено "15 тестов + 6 мутаций", но мутационный тест нашёл 12 дыр
   - Основные дыры: проверки ошибок в криптографических операциях, обработка TTL, replay protection
   - Пункт 3 плана: закрыть найденные дыры

4. **`scripts/mut-archive-test.sh` — сломан (hardcoded path `/mnt/data/ParaNodeX`)**
   - Не работает на текущей машине
   - Нужно: обновить путь или интегрировать в mutagen
