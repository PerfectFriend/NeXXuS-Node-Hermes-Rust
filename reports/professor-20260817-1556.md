## Summary

Studied Spec-Driven Development (SDD) using GitHub Spec Kit (130k+ stars, v0.14.4, July 2026 release). SDD inverts the traditional power structure: specifications become executable, directly generating working implementations rather than just guiding them. Code serves specifications (not vice versa).

### Core Concept

- **PRD → implementation generation**: Technical plans produce precise definitions that output code
- **Code serves specifications**: Specifications are the source of truth, not documentation after-the-fact
- **Test-first imperative**: NO code before tests (NON-NEGOTIABLE TDD)

### The Constitution (9 Articles)

1. **Library-First Principle** — Every feature begins as standalone library
2. **CLI Interface Mandate** — All libraries expose functionality via CLI (stdin/stdout, JSON)
3. **Test-First Imperative** — NO code before tests (NON-NEGOTIABLE TDD)
4-5. **Project-Defined** — Integration testing standards, observability requirements
6. **Project-Defined** — Versioning/breaking changes
7. **Simplicity** — Max 3 projects, no future-proofing
8. **Anti-Abstraction** — Use framework directly, single model representation
9. **Integration-First Testing** — Real databases, actual services, contract tests mandatory

### 7-Step SDD Workflow

```bash
# 1. Install
uv tool install specify-cli --from git+https://github.com/github/spec-kit.git@v0.14.4

# 2. Initialize
specify init my-project --integration copilot

# 3. Constitution
/speckit.constitution "Project governing principles..."

# 4. Spec (WHAT/WHY)
/speckit.specify "Feature description..."

# 5. Plan (HOW - tech stack)
/speckit.plan "Go + gRPC + YOLOv11n + ONNX DirectML..."

# 6. Tasks
/speckit.tasks

# 7. Implement
/speckit.implement
```
