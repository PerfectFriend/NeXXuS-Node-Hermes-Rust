## 3. HarnessMM — что извлечено (конспект целиком в Хранилище)

**Ключевое:** харнесс заново зовёт модель после каждого receipt инструмента, даже когда предыдущий вызов уже определил следующее действие. HarnessMM вставляет контроллер **на границе «модель–инструмент»**: веса модели зафиксированы, меняется **когда** харнесс зовёт рассуждение.

Три механизма (§4):
- **EDG** — узел `d_j = (a_j, arg_j, pred_j, g_j)`: действие, **полные буквальные аргументы**, причинная зависимость, **публичный guard**.
- **GDR** — `eligible = 1{pred completed} · 1{guard(s_t)=true} · 1{args closed}`; guard читает **только наблюдаемые receipts**; селектор типизирован и **воздерживается**, а не переписывает аргументы.
- **CCS** — сертификат `κ_t = (CLOSE, graph_hash, decision_id, predecessor_receipt, OPEN, exact_args, tool_receipt, bypassed_callback_id)`; аудит требует `N_slow,parent − N_slow,HarnessMM ≥ 1` — медленный колбэк **действительно** не вызван.

Две рамки важнее самого метода:
- **Substitution Paradox:** быстрый слой, ничего не убирающий, **увеличивает** стоимость (`C_n + C_f`). Выигрыш есть только при `C_removed > C_introduced` (включая авторство, роутинг, контекст, fallback, recovery).
- **Complete-Task Accounting:** считается **вся** стоимость эпизода, включая неуспешные платные вызовы и кэшированный вход; `C_dev` — отдельно, с амортизацией `C_dev/N`. Авторы прямо: токенная экономия ≠ экономия задержки/энергии.

Ограничение качества — `min_π C(π)` при `R_b(π) ≤ ε_b`, где `ε_b` фиксируется **до** оценки (zero-regret ⇒ `ε_b = 0`).

## 4. Пять правил для всей Машины Кода

1. **Повторное «прочитай и прими решение» — чинимый дефект харнесса, а не свойство модели.** Наш контур «кодер → аудитор → починка» платит полным рассуждением за каждое решение, которое было принято ходом раньше.
2. **Переиспользовать можно только доказуемо закрытое:** буквальные аргументы + наблюдаемый receipt + явная зависимость. Остальное — к модели.
3. **«Дешевле» без сертификата снятия колбэка — маркетинг.** Нужен счётчик медленных вызовов (родитель ≥ варианта) плюс отпечаток графа и ID пропущенного колбэка. **У нас такого счётчика нет вообще.**
4. **Стоимость считается целиком** — включая fallback, неуспешные платные вызовы и финализацию. Иначе «экономия» = перенос расхода в другое место.
5. **«Проходящий guard доказывает объявленное публичное условие, а не правильность задачи»** — ровно наш класс «зелёный гейт после первого падения»: гейт не должен выдавать себя за доказательство правильности.

**Зацепки по ролям.** Кодерам: минимальная единица реюса — «действие + буквальные аргументы + guard по наблюдаемому receipt». Аудитору: вердикт обязан иметь корзины `measured` (фактический вывод проверки) и `judged` (мнение) — у HarnessMM это выражено кодом (receipt против сертификата). Владыке: внедрять (если) — начиная с одного харнесса `orchestration/` и одного набора задач; замер = счётчик медленных вызовов + полная стоимость эпизода. Наш `journal.md` хранит свободный текст ⇒ машинный слой «решение принято, аргументы буквальны, зависимость от receipt X» надо строить отдельно.
