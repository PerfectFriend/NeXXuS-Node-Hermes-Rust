## Что конкретно сделано по теме 7

Прочитано **12 RFC** напрямую с `rfc.earendil.com` (без логина, все HTTP 200):
0001, 0002, 0015, 0019, 0020, 0031, 0038, 0039, 0043, 0044, 0047, 0054.

**Главный результат — отрицательный и это ценность:** в RFC Earendil **нет** ни
`durable`, ни `checkpoint` агента, ни «протокола сообщение за сообщением». Слова встречаются
только в значениях «долговечный формат RFC» и «checkpoint метаданных модели». Обещание
из поста `earendil.com/posts/pi-durable/` релизом не подтверждается — совпадает с уже
зафиксированным в учебнике по Pi 1.0.

**Взято в Живой Код:**
- RFC 0043 `PI_EXPERIMENTAL=1`: экспериментальное охраняется на границах продукта
  (регистрация команд, setup-flow, auth-провайдеры, UI-точки, workflow); по умолчанию
  поведение production-ready. → **критерий для наших гейтов: экспериментальная функция,
  видимая в проде без флага, — дефект.**
- RFC 0019/0038/0044: аналитика только opt-in, отказ = успешное завершение setup,
  `settings.json` = completion marker (дешёвый способ отличить «настроено» от «не настроено»
  — пригодится `cycle_claim_gate.py`).
- RFC 0020: предсказуемость под нагрузкой вместо состязания в изобретательности —
  прямой аргумент в пользу детерминированных гейтов вместо LLM-судьи.
- RFC 0031: «не гарантируем отсутствие регрессий» как конструктивная формулировка границы.
- RFC 0047: locked install — reproducibility против composability, именованный компромисс.
- RFC 0054: инструкции и определения инструментов переносятся в упорядоченные context items.
- RFC 0001: RFC как ранний долговечный черновик. Темы с 🔴 в нашем [[Учебник]] — это черновики,
  а не «неактуальное».
