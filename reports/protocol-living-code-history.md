## 📖 История создания

### Этап 1: Ранняя архитектура (до 2026-08-16)

Изначальная схема Живого Кода базировалась на **4-hour cycle** с плотной упаковкой агентов внутри 4-часовых блоков. Основные проблемы:

- **Рассинхронизация**: агенты запускались одновременно, боролись за GPU
- **Простои**: между 4-часовыми блоками протокол бездействовал по 3+ часа
- **Драка за ресурсы**: 4 кодера, 2 художника, профессор и Искатель стартовали в одну минуту
- **Нет триггеров**: агенты не знали кто и когда их вызывает
- **Нет журнала переписки**: кодеры не общались между собой

### Этап 2: Проектирование новой схемы (2026-08-16)

На основе пользовательского протокола (см. `протокол живого кода.md`) была спроектирована **часовая цикличность** вместо 4-часовой:

| Принцип | Решение |
|---------|---------|
| Последовательность вместо параллелизма | 10-минутные слоты внутри часа |
| Триггеры вместо крон-координации | `[TRIGGER_*]` метки в журнале |
| Разделение моделей | Кодеры — тяжёлые, Искатель/Профессор — lightning |
| Журнал как единая точка связи | Heartbeat каждые 10 минут |
| Супервайзер с реальными правами | Может pause/resume/update кроны |

### Этап 3: Реализация (2026-08-16, вечер)

- ✅ Удалено 14 старых кронов (LV-pulse-watchdog, LV-encrypted-comm, LV-model-registry-health, LV-professor-sync, LV-textbook-learning, LV-banner-deploy, LV-dj-studio, LV-holy-deploy, LV-flash-backup, LV-supervisor, 4 кодера)
- ✅ Создано 14 новых кронов по протоколу
- ✅ Созданы структуры: `agents/journal.md`, `reports/`, `textbook/`, `knowledge-base/`
- ✅ Создан скрипт `journal_comm.sh` для heartbeat
- ✅ Оставлено 5 инфраструктурных кронов (extinction, graph-export, vault-sync, backup-skills, key-rotation)

## 🔄 Четыре цикла Протокола

### 🔍 Цикл 1: Самообучение

```
:50  ИСКАТЕЛЬ → :55  ПРОФЕССОР
```

| Агент | Время | Модель | Задача |
|-------|-------|--------|--------|
| 🔍 Искатель | `:50` каждый час | nemotron-3.5-lightning | Поиск новостей AI/Code, закачка софта по запросам агентов, раскладка по учебнику [NEW] |
| 🎓 Профессор | `:55` каждый час | nemotron-3.5-lightning | Изучение 1 темы из учебника, конспект, база знаний, [STUDIED] |

**Поток данных:**
1. Искатель читает журнал → находит запросы кодеров
2. Ищет в соцсетях, GitHub, топ-20 IT порталах
3. Скачивает/устанавливает софт (единственный с правом установки)
4. Раскладывает новости по учебнику с метками [NEW] и приоритетами
5. Триггерит Профессора: `[TRIGGER_PROFESSOR]`
6. Профессор изучает 1 тему → конспект → база знаний → [STUDIED]
7. Оба отправляют MD-отчёты Инквизитору

### ⚖️ Цикл 4: Контроль и Гармония

```
:35  ИНКВИЗИТОР → :45  СУПЕРВАЙЗЕР
```

| Агент | Время | Задача |
|-------|-------|--------|
| ⚖️ Инквизитор | `:35` каждый час | Сбор всех отчётов, решение проблем, [DEPLOYED] в базу знаний |
| 👁️ Супервайзер | `:45` каждый час | Мониторинг, tune кронов, предотвращение драк за ресурсы |

**Инквизитор:**
- Читает все отчёты за час
- Решает проблемы: fix кода, fix кронов, fix конфига
- Переводит темы учебника [STUDIED] → [DEPLOYED]
- Записывает `[KNOWLEDGE_BASE_UPDATED]` в журнал

**Супервайзер:**
- Анализирует телеметрию за 2 часа
- Проверяет что все агенты отработали
- Разносит одновременные запуски по времени
- Ускоряет протокол без рассинхронизации
- Может pause/resume/update любые кроны

## 📝 Журнал переписки

**Скрипт:** `journal_comm.sh`  
**Расписание:** `*/10 * * * *` (каждые 10 минут)  
**Назначение:** Heartbeat-запись в `/home/thomas/LivingCode/agents/journal.md`

Каждые 10 минут агенты-кодеры:
1. Читают журнал переписки
2. Оставляют свои заметки, обращаясь друг к другу по имени и отчеству
3. Проводят мозговые штурмы
4. Направляют запросы Искателю на поиск информации

**Кто из них кто** — агенты придумывают себе имена при первом запуске и фиксируют в журнале:
- Кто на каком хосте живёт
- Какие задания выполняет
- Какие проблемы нашёл

## 🛡️ Защита от драки за ресурсы

| Модель | Агенты | Когда | Конкуренция |
|--------|--------|-------|-------------|
| Тяжёлая (super-coder) | 4 Кодера | :00 (1 за раз) | ❌ Нет — по очереди |
| Тяжёлая | Аудитор, Владыка | :15, :20 | ❌ Нет — после кодера |
| Средняя | Продюсер, Художники | :25, :30, :40 | ❌ Нет — разные слоты |
| Lightning | Искатель, Профессор | :50, :55 | ❌ Нет — лёгкая модель |
| Lightning | Инквизитор, Супервайзер | :35, :45 | ❌ Нет — лёгкая модель |
| Bash-скрипт | Журнал, Ключи | :00,:10,... / :00,:30 | ❌ Нет — без LLM |

**Принцип:** в любой момент времени работает **не более 1 тяжёлого агента** + лёгкие агенты запускаются в непересекающиеся слоты.

## 🎯 Система меток учебника

| Метка | Цвет | Значение | Кто ставит |
|-------|------|----------|------------|
| `[NEW]` | 🔴 Красный | Новый материал для изучения | Искатель |
| `[STUDIED]` | 🟡 Жёлтый | Изучен, конспект готов | Профессор |
| `[DEPLOYED]` | 🟢 Зелёный | Задеплоен в базу знаний | Инквизитор |

**Поток:** Искатель находит → [NEW] → Профессор изучает → [STUDIED] → Инквизитор деплоит → [DEPLOYED] → `[KNOWLEDGE_BASE_UPDATED]` в журнал → все агенты на следующем цикле подгружают новые знания.

## 📌 Итог

Протокол Живого Кода v2.0 — это **11 агентов**, работающих в **4 циклах**, разбитых на **10-минутные слоты** внутри каждого часа. Схема обеспечивает:

- ✅ **Последовательность** — ни один тяжёлый агент не конкурирует с другим
- ✅ **Триггеры** — агенты вызывают друг друга через метки в журнале
- ✅ **Журнал** — единая точка общения, heartbeat каждые 10 минут
- ✅ **Самообучение** — Искатель + Профессор на лёгкой модели, не мешают кодерам
- ✅ **Контроль** — Инквизитор собирает отчёты, Супервайзер tunит кроны
- ✅ **Без простоев** — каждый час = полный цикл, 24/7
