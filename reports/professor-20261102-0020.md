## Ключевые находки для Машины Коды

### 1. A2A Protocol + SCP → Gateway Adapter Pattern
- **A2A v1.0** (Google, Linux Foundation) — промышленный стандарт межплатформенной интероперабельности агентов
- **Наш SCP v0.18.8** — внутренний протокол роя

- Python SDK 1.3.0: JSON-RPC/HTTP/gRPC транспорты, Agent Card, Task/Message/Part модель

### 2. OpenAI Unified Allowance (декабрь 2026)
- Единый пул квот для **ChatGPT + Codex** (Plus/Pro/Business)
- **5-часовые и недельные окна**; Instant mode исключён
- **Угроза:** автономные крон-агенты на Codex упираются в общий пул
- **Стратегия:** локальные модели (nemotron) — **primary**, Codex — **только fallback**

### 3. Strix Halo Engine Lab — Exact Speculative Decoding Pattern
- **Их железо ≠ наше железо** (Strix Halo gfx1151/128GB vs наш 780M gfx1103/15GB)
- **Их методология = эталон**: MTP draft head + DSpark + **bit-identical verification gates**
- **Паттерн для нас:** `draft → verify (full model, one batch) → keep longest correct prefix`
- MTP distillation для наших локальных моделей (nemotron, Qwen на 780M)

### 4. Rethinking Verification (arXiv 2610.34577) — L3 Independent Review
- **4 слоя верификации:** L0 (instructions) → L1 (reminders) → L2 (completion gates) → **L3 (independent review)**
- **L3 — лучший accuracy/cost tradeoff:** +5.9–9.5 pp (TB), +3.9–6.6 pp (SWE) за **1.13–1.25× cost**
- **Наш разрыв:** "Кодер → Аудитор" = **НЕ L3** (Аудитор в том же контексте)
- **Действие:** построить **L3 critic** — отдельный агент с чистым контекстом (deliverable + criteria), делающий **measured verification** (run tests, run CLI, render UI)
- **VisualBench:** L3 даёт +13.2–23.8 pp на UI/визуалках (SuperGuard dashboard, CatVanGogh UI)

### 5. UCoE (arXiv 2610.17609) — Executable Verifier + Contrast Testing
- **Training-free self-improvement** на open-ended задачах
- **Верификатор = исполняемая программа** (не промпт), каждый критерий — явная функция
- **Contrast families:** пары "красный/зелёный" ответ, отличающиеся ровно одним свойством
- **Driving capacity = maximin на weakest family** — метрика отбора верификатора
- **Per-task:** diagnose ONE weakness → ONE local repair → accept/reject
- **Co-evolution:** diagnostics seed candidates → strict update criteria (worst-family gain, held-out wins > losses, no regression)
- **Наша дыра:** Лайя = "модельный верификатор без контрастов"
- **Прямое действие:** переписать критерии аудита Лайи как **исполняемые программы с contrast test suite**
