## Что измерил (проба, ничего не утверждала)

Поднял настоящий TCP-обмен с обработчиками через `handleConn` — тем же
путём, куда приходит трафик из сети. Проба записана файлом, читала файлы и
печатала измеренное:

| Запрос | Ответ узла | Что это значит |
|---|---|---|
| `file_req path=../peer_cache_EVIL/loot.txt` | `"SIBLING-LOOT"` | прочитан файл из соседнего каталога |
| `track_req track_id=../../secret.txt` | `"TRACK-SECRET"` | прочитан файл вне кэша |
| `piece_req hash=../../secret3.txt` | `"PIECE-SECRET-0123..."` | прочитан файл вне кэша |

Первая строка — самая показательная. Кэш лежит в `dataDir/peer_cache`,
а рядом стоит `dataDir/peer_cache_EVIL`. Проверка была строковой:

```go
fullPath := filepath.Join(t.cacheDir, filepath.Clean(req.Path))
if !stringsHasPrefix(fullPath, t.cacheDir) { ... }
```

`/data/peer_cache_EVIL/loot.txt` начинается с `/data/peer_cache` — префикс
совпал, защита пропустила. Проверка сравнивала начало строки вместо границы
каталога.

## Подтверждено достижимостью

Не «мёртвый код в вакууме»: `cmd/ParanoidX/main.go:2228` вызывает
`transport.NewTransfer(...)` и `p2pTrans.Start()` на старте, порт из
`P2P_PORT` (по умолчанию 17001), адрес публикуется в реестр узлов. То есть
обработчики достижимы из сети.

## Что менял

`internal/transport/transfer.go`:

- **`resolveInCache`** вместо строкового префикса. Граница сверяется по
  разделителю: `full != base && !hasPrefix(full, base + "/")`. Обе стороны
  нормализует `filepath.Join` сам, симметрично — иначе relative `cacheDir`
  перестал бы совпадать сам с собой и закрыл бы весь доступ.
- **`safeName`** для удалённых имён (id трека, хеш куска): только одиночное
  имя, оба слеша отвергаются, `.`/`..`/пустое — тоже.
- **`handleTrackReq`** и **`handlePieceReq`** получили проверку `safeName` —
  раньше там не было никакой.
- **`handlePieceReq`**: граница диапазона и отсечение по фактически
  прочитанному. Отрицательный `size` из сети ронял `make([]byte, size)`,
  а запрос за концом файла отдавал хвост памяти узла.

`internal/transport/transfer_test.go` — 12 тестов, все через настоящий
сетевой обмен. Плюс `scripts/mut-transfer-boundary.sh` — мутационный гейт.

## Мутация (обязательный шаг, правило 1)

Гейт снимает по одной защите и ждёт падения. Первый прогон дал
**PASS=6 FAIL=3** — три мутации выжили. Это находка, а не отговорка:

1. **Отсечение хвоста и игнор ошибки чтения** не ловились: `TestPieceReqSlicesRequestedRange`
   сравнивал `payload[:3]`, а при мутации там было 10 байт — JSON-экранирование
   нулями съедало разницу в первых символах. Написал тесты, которые меряют
   ДЛИНУ ответа: `TestPieceReqDoesNotLeakPastEndOfPiece` (offset=8 size=10 на
   файле в 10 байт → ждём ровно "89") и `TestPieceReqRejectsRangePastEndOfPiece`
   (offset=50 → отказ, а не пустой «кусок»).
2. **Мутация нормализации** оказалась некорректной по существу: `base` уже
   абсолютный, поэтому снятие `Abs` у `full` физически ничего не меняло.
   Проверил и убрал мёртвый код, а гейт перевёл на реальный класс регрессии —
   асимметричную нормализацию (абсолютна только одна сторона). Ловится.

Финальный прогон: **PASS=10 FAIL=0**. Гейт также проверяет, что
`transfer.go` после прогона совпал с бэкапом побайтово.
