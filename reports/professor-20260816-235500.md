## 🔑 Key Insights Extracted

### 1. **Spec-Driven Development (SDD) — Fundamental Inversion**
> "Specifications don't serve code—code serves specifications. The PRD isn't a guide for implementation; it's the source that generates implementation."

- Eliminates the spec↔code gap by making specs **executable**
- Code becomes "last-mile expression" of intent in a particular language/framework
- Maintenance = evolving specifications, not patching code

### 2. **The 9-Article Constitution (Architectural DNA)**

| Article | Principle | Enforcement |
|---------|-----------|-------------|
| I | Library-First | Every feature = standalone library |
| II | CLI Interface | stdin/stdout, JSON for all libs |
| III | Test-First | **NON-NEGOTIABLE**: Tests before code (TDD) |
| IV-VI | Project-Defined | Integration, observability, versioning |
| VII | Simplicity | ≤3 projects, no future-proofing |
| VIII | Anti-Abstraction | Use framework directly |
| IX | Integration-First | Real DBs, actual services, contract tests |

### 3. **Specify CLI — The Execution Engine**

**Core Commands:**
```
/speckit.constitution  → Project governing principles
/speckit.specify       → What to build (WHAT/WHY)
/speckit.plan          → Tech stack & architecture
/speckit.tasks         → Executable task list
/speckit.implement     → Build from tasks
/speckit.converge      → Assess codebase vs spec
/speckit.analyze       → Cross-artifact consistency
/speckit.checklist     → Quality gates ("unit tests for English")
```

**Extensibility Systems:**
- **Extensions** — New capabilities (Jira, code review, V-Model)
- **Presets** — Customize workflows (compliance, Agile, security gates)
- **Bundles** — Role-based setups (PM, BA, Security, Developer)

### 4. **Template-Driven LLM Constraints (Quality Engineering)**

The templates act as sophisticated prompts that constrain LLM behavior:
1. **No premature implementation** — Focus on WHAT/WHY
2. **Explicit uncertainty markers** — `[NEEDS CLARIFICATION: question]`
3. **Structured checklists** — Completeness verification
4. **Constitutional gates** — Phase -1 enforcement
5. **Hierarchical detail** — Code in `implementation-details/`
6. **Test-first ordering** — Contracts → Tests → Implementation
7. **No speculative features** — Every feature traces to user story
