## 3. Замечания (адресно Фратеру Abyssus)

### №1 [Н] Фабричный мок `ollama` без `importActual` — мина на будущее
`src/hooks/useTarot.integration.test.ts:19–21`. Фабрика возвращает объект только с `ollamaInterpret`. Сегодня это безопасно (в модуле ровно один `export`), но при добавлении второй функции в `src/services/ollama.ts` (например, стриминговая интерпретация) тест упадёт с `is not a function` **не там, где ошибка**, а в глубине `interpret()`. Как исправить:

```ts
vi.mock('@/services/ollama', async () => {
  const actual = await vi.importActual<typeof import('@/services/ollama')>('@/services/ollama');
  return { ...actual, ollamaInterpret: vi.fn().mockResolvedValue(null) };
});
```

### №2 [Н] Магические числа и рукописная схема состояния в тестах
Строки 46–60 (`seedState`) и 91–107 воспроизводят форму state и константы экономики руками (`40`, `60 + 24`, `100`). Сейчас значения совпадают с кодом (проверено), но тест станет ложным при правке балансов: он будет выглядеть как «сломался тест», а не «изменили экономику». Дешевле: `import { RARITIES } from '@/data/game'` и `const rareCost = RARITIES.rare.cost`, а `seedState` собирать из экспортируемого дефолта состояния (если `useTarot.ts` его экспортирует) либо через `INITIAL_STATE`-константу, чтобы новая обязательная ветка state ловилась компилятором, а не молча обходилась моком.
Отдельно: комментарий к `seedState` («как делает реальное приложение») — неточен, ключ `cybertarot-state` дублируется строкой в тесте; лучше импортировать константу ключа, если она экспортируется.

### №3 [Н-стиль] Вакуумный `waitFor` и глобальная заморозка таймеров
- Строка 116: `await waitFor(() => expect(result.current.balance).toBe(0))` — не проверяет ничего: `0` это и стартовое значение до `loadState`. Гидратацию на самом деле доказывает следующая строка `harvestReady === true` (она зависит от `well.pending = 40` из `seedState`). Замечание косметическое — но если из теста уберут `harvestReady`, ожидание станет ритуальным. Достаточно `expect(result.current.harvestReady).toBe(true)` и `waitFor` на признак, который инициализируется только после загрузки state.
- Корневая причина паттерна, который вы лечили в этом цикле, живёт в `vitest.setup.ts:28–29` (`vi.stubGlobal('setInterval', vi.fn(() => 0))` глобально для всех тестов): любой будущий тест на `waitFor`/поллинг будет тайно висеть или падать. Ваш обходной путь (`vi.stubGlobal` с реальными таймерами внутри файла) **корректен и локален** — подтверждаю, что он работает (тест идёт 35ms, поллинг реальный, `pollUntil` с timeout 5s). Но правильнее убрать глобальный стаб из setup и включать фейковые таймеры точечно (`vi.useFakeTimers()` в тестах колодца). Правка в `vitest.setup.ts` потребует прогнать весь набор — это отдельный маленький цикл (в этом диапазоне файл не менялся, поэтому формально вне горячего кода; отмечаю как долг).

### Наблюдения без действия
