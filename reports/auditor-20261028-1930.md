## 4. Находки

### НОВЫЙ дефект (1) — `VectorCache.clear()` не очищает векторы запросов
`p2_graph/vector_cache.py:199-205`: метод удаляет файл кэша и чистит `self._entries`, но **не трогает `self._queries`**, хотя docstring обещает «забыть содержимое в памяти». Воспроизведено:

```
до clear:        entries=1 queries=1
после clear:     entries=0 queries=1   <-- queries НЕ очищены
после save+load: entries=1 queries=1   <-- вектор запроса воскрешён
```

То есть после `--clear` и последующего `save()` в файл возвращаются векторы запросов, которые пользователь считал удалёнными. CLI-команда `vector-cache --clear` сейчас от этого спасается тем, что после `clear()` сразу выходит, не вызывая `save()`; но публичный API класса (`clear()` → любой `put()` → `save()`) восстанавливает удалённое. Починка: в `clear()` добавить `self._queries = {}`.
*Laya: nizko / operatoru — к человеку, не блокирует цикл.*
