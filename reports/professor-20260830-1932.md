## Кратко о каждом фреймворке

### PocketFlow
- **Ключевая идея**: 100-строчный минималистичный фреймворк на концепции Graph + Shared Store.
- **Плюсы**: Очень лёгкий (~56KB), нулевые зависимости, языковая и платформ-агностическая реализация (есть порты на TS, Java, C++, Go, Rust, PHP).
- **Минусы**: Слишком низкоуровневый – нужно вручную реализовывать узлы и действия для типовых паттернов.
- **Где полезен**: Для локальных устройств с ограниченными ресурсами, когда нужен контроль над каждой деталью графа агентов.
- **Интеграция с локальным LLM**: Отлично подходит для llama.cpp – можно обернуть вызовы в узлы типа `LLMNode`.

### Strands Agents SDK
- **Ключевая идея**: Production-ready SDK от AWS (но открытый) для построения агентов на Python/TypeScript с end-to-end управлением harness.
- **Плюсы**: Поддерживает любые модели и облака, имеет встроенные инструменты (tools), цикл наблюдения-действия-рефлексии, прост в развёртывании.
- **Минусы**: Больше зависимостей и "веса", чем PocketFlow; ориентирован на облачные сценарии.
- **Где полезен**: Для продакшн-агентов, которым нужна надёжность, масштабируемость и богатый набор готовых компонентов.
- **Интеграция с локальным LLM**: Можно подставить локальный эндпоинт llama.cpp через совместимый API (например, OpenAI-совместимый).

### OpenClaw
- **Ключевая идея**: Кроссплатформенный личный AI-ассистент с 387k звёзд на GitHub (TypeScript/React Native).
- **Плюсы**: Готовый продукт с голосовым вводом, экранным выводом, навыками (skills), поддержкой Android/iOS/Web/Desktop.
- **Минусы**: Тяжелее, фокусируется на конечном пользователе, а не на гибкой кастомизации ядра.
- **Где полезен**: Как референсная реализация для создания собственного ассистента на PXNode с учётом локальных моделей.
- **Интеграция с локальным LLM**: Через pluggable провайдеры – можно подключить llama.cpp как локальный бэкенд.

### PageIndex
- **Ключевая идея**: Vectorless, reasoning-based RAG-фреймворк, заменяющий векторные БД на дерево документа + LLM-рассуждения.
- **Плюсы**: Поражающая точность (98.7% на FinanceBench против 30-50% у векторного RAG), отсутствие эмбеддингов и чанкинга, работа с длинными документами через логическое навигация.
- **Минусы**: Медленнее при больших деревьях из-за множества LLM-запросов на шагах поиска; требует мощной модели для рассуждений.
- **Где полезен**: Для работы с закрытыми документами ParanoidX (логи, аудиты, политики), где важна точность, а не скорость.
- **Интеграция с локальным LLM**: Требует двух моделей: lightweight для построения индекса и мощный для чат/рассуждений – можно использовать quantized llama.cpp для обеих.

### Langextract
- **Ключевая идея**: Извлечение структурированной информации из неструктурированного текста с точным source grounding (привязка к оригиналу).
- **Плюсы**: Гарантированная привязка извлечения к source text, визуализация результатов, оптимизация для длинных документов (chunking + параллелизм), поддержка few-shot инструкций.
- **Минусы**: Сфокусирован только на извлечении, а не на генерации или агентных циклах.
- **Где полезен**: Для автоматизации обработки отчётов, логов, юридических документов в ParanoidX – извлечение сущностей, событий, показателей.
- **Интеграция с локальным LLM**: Работает с Ollama (llama.cpp сервер) из коробки.

## Выводы и рекомендации для ParanoidX/PXNode

1. **Для ядра агентов PXNode** (VPN-цепочки, мониторинга, самовосстановления): рекомендуется **PocketFlow** из-за минимализма и предсказуемого поведения. Можно построить узлы для:
   - Проверки состояния VPN-цепочки
   - Тестирования Tor-выходов
   - Запуска аудит-проверок
   - Принятия решений о перезапуске сервисов

2. **Для высокоуровневых задач** (взаимодействие с пользователем, сложное планирование): **Strands Agents SDK** или **OpenClaw** как основа – предоставляют готовый harness и навыки (skills), которые можно кастомизировать под локальные модели и специфику ParanoidX (например, навык для работы с Polymarket через SOCKS5-прокси).

3. **Для работы с внутренними знаниями** (аудит-журналы, конфиги, политики): **PageIndex** позволяет создавать точные векторless RAG-базы из документов в Obsidian Vault и локальных логов, что критически важно для принятия обоснованных решений без утечки данных.

4. **Для обработки входных потоков** (логи мониторинга, отчёты систем, telegram-сообщения): **Langextract** автоматизирует извлечение ключевых фактов, событий, метрик с гарантией source grounding – можно построить дашборд показателей или систему алертов на основе извлечённых сущностей.

5. **Гибридный подход**: Комбинировать фреймворки – например, использовать Langextract для предварительной обработки текста, затем PageIndex для семантического поиска по извлечённым структурам, и наконец PocketFlow/Strands для агентного принятия действий на основе полученных знаний.
