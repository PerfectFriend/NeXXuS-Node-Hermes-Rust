## 3. Что извлечено (кратко, самое ценное)

### A2UI — генеративный UI как структурная граница доверия
- Агент возвращает **декларативное описание компонентов из одобренного каталога**; клиент рендерит своими нативными виджетами. Произвольный код не исполняется ⇒ **нет UI-injection**.
- Версии: v1.0 (candidate, `actionResponse`/RPC), v0.9.1 (production, `application/a2ui+json`), v0.9 (Prompt-First, `createSurface`, клиентские функции), v0.8 (legacy).
- Формат — **плоский потоковый JSON**: LLM строит UI инкрементально ⇒ progressive rendering.
- Разграничение: **MCP** = инструменты, **A2A** = агент↔агент, **AG-UI** = бэкенд↔приложение (SSE), **A2UI** = язык описания UI.
- **Для нас:** наш UI-гейт обязан быть каталогом, а не escape-hatch; ограничение поведения структурное, а не просительное.

### llama.cpp Vulkan: буферы, MTP, регрессии Ollama
- PR #23973 — быстрый путь **непрерывного** переноса буферов CPU↔GPU; на UMA (780M) это главный потолок. Конкретных цифр ускорения автор не даёт — на 780M не измерено.
- PR #24240 — `GGML_VK_NODES_PER_SUBMIT` (размер батча отправки); PR #24215 — непрерывные Unary/GLU; PR #23398 — Gemma 4 MTP (WIP): **dense >2× скорости, на MoE ускорения нет**.
- **Ollama 0.30.x на AMD — блокер:** #16564 OOM на больших GGUF, #16570 зависание на мультимодальности, #16569 «значительно медленнее» llama.cpp, #16572 падение при нескольких GPU. Рекомендация: держать **0.24.0** или уйти на llama.cpp напрямую.
- **Для нас:** политика заморозки локального стека на 780M; `GGML_VK_NODES_PER_SUBMIT=1` + `-ngl 9999` как базовый профиль.

### llama.cpp Vulkan на 780M — реальные цифры (тред #27519)
- gpt-oss 20B MXFP4 (11.27 GiB): pp512 **403.22 tok/s**, tg128 **29.39 tok/s**; при d=32768 — pp **62.31**, tg **20.84**.
- Qwen3.6-35B-A3B Q8_0 (34.36 GiB): pp512 **325.12**, tg128 **20.48**; при d=32768 — pp **131.61**, tg **16.68**.
- Коллапс prefill из issue #15163 — **не общий для AMD iGPU**: 62–132 tok/s против «20 tok/s» из issue.
- **Для нас:** проектировать агента под **prefill**, а не decode (20k токенов ⇒ ~5.4 мин на заход при 62 tok/s); A3B-класс — только в Q4/MXFP4, Q8 в 32 GB UMA впритык.

### OpenAI Agents SDK HITL — протокол прерывания
- `needs_approval=True` или async-callable; **fail-closed**: битый/пустой/невалидный JSON ⇒ ручное одобрение, никогда автозапуск.
- Протокол: пауза → `RunResult.interruptions` (`ToolApprovalItem`) → `to_state()` → `approve/reject` → `Runner.run(agent, state)`. Граница одобрения — **весь run**, включая handoff и вложенный `Agent.as_tool()`; частичное решение разрешено.
- Липкие `always_approve/always_reject` переживают сериализацию `RunState` — **отдельный рычаг риска**.
- Run-state сериализуется и переживает процесс ⇒ одобрение — это запись в состояние, а не диалог. `context_override`/`strict_context` **не делают** snapshot доверенным: нужны проверка целостности, привязка к пользователю/run'у и защита от replay; секреты в `context` класть нельзя.
- **Для нас:** гейт = сериализуемый чекпоинт прогона; `always_*` — запретить по умолчанию; A2UI + HITL = готовый UI-гейт (что нужно + как показать).

### Mozilla: конфигурация важнее движка
- Все четыре движка (llama.cpp / llamafile / LM Studio / Ollama) — **одно llama.cpp-ядро**; после контроля весов и флагов они сходятся в пределах единиц процентов по prompt processing.
- CUDA graphs: decode **+16.8%** (0.8B), +6.5% (9B), +4.3% (27B) на L40S.
- Свежий шейдерный тулчейн Vulkan (LunarG Vulkan SDK 2026.03 против системного shaderc 2023.8), Steam Deck: prompt processing **+25.9%** (0.8B), **+63.3%** (9B); decode +18.2% (9B).
- Разрыв decode — **постоянный host-overhead**: 0.4 мс/токен (Mac), 1.8 мс (L40S), 5.4 мс (Deck) — почти не зависит от размера модели.
- Лучший draft-спекулятивного декодера зависит от платформы (Metal → 2, CUDA → 4). В llamafile 0.9.2+ есть **LocalScore** (`./llamafile --localscore`).
- **Для нас:** самый дешёвый прирост на 780M — пересборка против свежего LunarG Vulkan SDK; в профиле стенда хранить **мс/токен**, а не только tok/s.
