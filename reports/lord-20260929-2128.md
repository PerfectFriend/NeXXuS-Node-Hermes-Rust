### №1 [СР] Алиасинг `shared_state` — реестр движков PLAN #15 не работает
`self.shared_state = shared_state or {}` — пустой переданный словарь **не алиасится** (falsy → создаётся новый).
Мой пробник (`~/.hermes/cache/scratch/lord_el2_hot_probe_20260929.py`):

```
engine.shared_state is caller dict: False      ← пустой словарь НЕ общий
caller dict after sync of 1 engine: {}         ← запись ушла в приватную копию
second engine sees engine_count = 1 (expected 2)
non-empty caller dict is shared (aliased) : True   ← с непустым — общий
```

Т.е. дефект проявляется **ровно в штатном сценарии** (первый движок стартует с пустым общим состоянием), а с непустым — скрыт. Фикс: `if shared_state is None: shared_state = {}` + `self.shared_state = shared_state`. Два красных теста закрываются этим фиксом.

### №2 [СР] `rollback()` и `reset()` молча снимают FROZEN
Класс, который Аудитор уже фиксировал у superguard (`reset()` в обход FROZEN). Прогон:

```
after freeze: status=FROZEN cycle=4
has unfreeze(): False
rollback(1) on FROZEN -> Rolled back to cycle 1 (subcycle 2)
after rollback: status=EVOLVING cycle=1
evolve() after rollback -> {'status': 'success', ...}
reset() while FROZEN -> status now: EVOLVING
```

Заморозка обходится в один вызов, при этом **явного `unfreeze()` в движке нет вообще** — единственный выход из FROZEN сейчас неявный (через rollback/reset). Фикс: ввести `unfreeze()` как единственный штатный выход и отказать `rollback()`/`reset()` при `status == "FROZEN"` (опционально `force=True`) + тесты-близнецы.

**Важно (снял ложную тревогу):** guard FROZEN в `evolve()` **цел** (цикл 14, `e640d43`) — проверено отдельно:
`evolve()` вернул `{'status': 'frozen', ... 'Evolve refused'}`, состояние не изменилось (`(4,5,FROZEN)` → `(4,5,FROZEN)`). Регрессии нет.
