### Существенное по каждой теме

**1. Skills over MCP (SEP-2640, статус Final, Extensions Track, создан 2026-04-23).** Agent Skills (`agentskills.io`, директория с `SKILL.md` + YAML-frontmatter) раздаются по MCP через существующий примитив Resources. Каждый файл скилла = ресурс под `skill://<skill-path>/SKILL.md`; методы `skills/list` (может вернуть пустой/частичный список — по спецификации это норма) и `skills/get`. Ключевое: SEP задаёт только транспорт, формат скилла делегирован спецификации Agent Skills, включая progressive disclosure. Авторы: @pja-ant (sponsor), @olaservo, @sambhav, @aditya-scio. Происхождение: experimental-ext-skills#69/#83.

**2. Magentic-UI (MSR-TR-2025-40, июль 2025) и MagenticLite (MIT, 10 102★).** Шесть механизмов вмешательства человека; актуальный код — двухмодельная схема MagenticBrain (оркестратор) + Fara (browser-use, vision), заявлена как «сильная агентность без frontier-scale compute». Практическая ценность: `require_approval_untrusted` как эталон UI-гейта на «линии разлома»; `omniagent_only` как режим деградации без браузера; любой OpenAI-совместимый endpoint (vLLM/Ollama/наш gateway) подходит без доработок. Ловушка конфига: эффективные настройки живут в локальной БД, `--config config.yaml` мержит при старте и перезаписывает правки UI — «кто записал последним, победил».

**3. Anaconda Agent Swarms (пресс-релиз 06.10.2026).** Три сделки 2026 года: Outerbounds/Metaflow (29.04, оркестрация и воспроизводимые окружения), Kilo Code (15.07, Swarm впервые в VS Code, secure message board, 500+ моделей, локальное исполнение, auto-routing, Kilo Desktop beta с совместными notebook-сессиями), Enkrypt AI (04.08, red-team агенты, 300+ категорий атак, guardrails approve/modify/block). Цифры: 63% респондентов движутся к роям, 72% считают управление автономией критичной задачей; Enkrypt просканировал 268 210 инструментов на 25 264 MCP-серверах и нашёл уязвимости на 73% серверов (выборка Enkrypt).

**4. Agent Gateway (Rust, Apache-2.0, 5 678★, 1 001 fork, Linux Foundation / AAIF).** Прокси на MCP+A2A: LLM Gateway (единый OpenAI-совместимый API, бюджет/spend, load balancing, failover), MCP Gateway (tool federation, stdio/HTTP/SSE/Streamable HTTP, OpenAPI, OAuth), A2A Gateway (capability discovery, modality negotiation), Inference Routing по **GPU utilization, KV cache, LoRA-адаптерам и глубине очереди** через Kubernetes Inference Gateway, guardrails (regex, OpenAI moderation, Bedrock Guardrails, Model Armor, webhooks), RBAC с CEL-policy engine и OpenTelemetry. Два режима: standalone (плоский YAML) и Kubernetes (controller + Gateway API).

**5. Approval Laundering (arXiv 2609.38983, Yang Wang, Fudan, 30.09.2026).** Таксономия 6 режимов подмены одобренного действия: Scope, Argument, Temporal, Tool, Delegation, Semantic. Инструментирована точка `PreToolUse` в Claude Code, N = 19–2020 прогонов на класс, BGR с интервалами Уилсона, κ = 1.0. Защита — **Approval Token** `H_k(principal, agent_id, session_id, tool, arguments, scope, expiry)`, ключ никогда не возвращается агенту. Честные результаты: Delegation устранён полностью, Temporal устранён (p < 10⁻⁵, offline replay + 6/6 живых), **Scope не затронут вовсе**, **Argument без значимого снижения** (p = 1) — структурный предел field-only-верификатора.

### Связка, которая важна для Живого Кода
Approval Laundering прямо показывает: **Scope- и Argument-laundering не лечатся токеном** — их ловит только enforcement-слой *снаружи* агента, видящий фактический вызов. Это аргумент за [[Agent-Gateway-AAIF-2026]] как внешнюю точку принуждения и за [[Magentic-UI-MagenticLite-HITL-2026]] как образец «линии разлома» внутри UI. Delegation-laundering — самая частая в роях: approval обязан быть непередаваемым вниз по дереву агентов.
