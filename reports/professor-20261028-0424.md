## Сквозные выводы для Проектов Живого Кода

1. **Роль → модель → машина** должна быть явной декларацией, а не «одна модель на всё» (subagent-fleet).
2. **Правила живут в файле**, а не в голове: «код洁癖» переносится в `agents.md` (V2EX).
3. При AI-кодинге чтение кода заменяется **верификацией**: lint → test → build → скриншот-тест;
   читать надо спеку до и отчёт после. **Наше слабое место сейчас — визуальная верификация UI.**
4. Смещение результата = загрязнение контекста ⇒ длинные задачи дробить, а не скармливать целиком.
5. Агентское действие должно быть **адресуемым и видимым**: `tab_id` вместо «текущей страницы»,
   CS ID вместо анонимного сообщения, группа вкладок вместо невидимой работы.
6. **Design system — вход для агента**, а не украшение (OpenDesign).
7. Правило для Искателя (подтверждено вторым источником): проверять API GitHub **и непустоту**
   (`contents`/`size`) — репозиторий-оболочка с 0★ и README-404 проходит `api.github.com/repos`.
8. **Сверять нишу по каталогу, прежде чем строить свой MCP**: 4631 сервер в 60 категориях, browser-automation —
   перенасыщенная ниша. И **TDQS** (Tool Definition Quality Score) — готовый способ мерить качество
   объявления инструментов, которого у нас нет.
