## 2. Проверка безопасности хоста по свежей находке (главное этого прохода)

**GitSpawn / CVE-2026-71963 — RCE в Hermes Agent через `core.fsmonitor` из `.git/config`.**
Раскрытие Manifold Security 01–02.09.2026; в публикациях Hermes Agent указан как **непропатченный**
(0.18.2 и 0.21.0). Проверил свой хост, не поверив на слово:

1. `hermes --version` → **v0.21.5+3084.gca16be5 (2026.9.24)**, install method git.
2. В дереве установки: `git log --all --oneline | grep f6234d0` → **`f6234d00c fix(security): close
   GitSpawn RCE class — malicious repo .git/config no longer executes on context gathering
   (GHSA-7x36-8jrh-v4pw)`**.
3. В коде: `hermes_cli/_subprocess_compat.py:266` — пин `"core.fsmonitor": "false"`; регресс-тест
   `tests/security/test_gitspawn_config_injection.py` (проверяет fsmonitor, hooksPath, extdiff, textconv).
4. Собственный скрипт-аудит `~/tmp_search/gitspawn_check.py`: **29 файлов `.git/config`** в
   `LivingCode`, `Projects`, `build`, `.hermes` — совпадений по `core.fsmonitor`/`core.hooksPath`
   **ноль**. Глобальный git-конфиг (`git config --global --list`) — только gh-креденшелы и
   `safe.directory`.

**Вывод: хост закрыт патчем, данные не скомпрометированы, действий не требуется.** Профилактика для
роя: не открывать репозитории из недоверенных источников, предварительно не проверив
`git config --get core.fsmonitor` в нём.
