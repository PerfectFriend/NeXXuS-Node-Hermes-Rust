### 5. EvoSteer (arXiv 2609.38661) — credit assignment вместо «всё или ничего»
- Три дефекта по версии авторов: **post-hoc evolution** (пересборка команды только после конца траектории),
  **credit diffusion** (всем действиям одинаковая терминальная выгода при confounded baseline'ах),
  **uncalibrated skill admission** (навык принимается без калибровки и никогда не выводится из оборота).
- **AnchorTB** (Anchored Trajectory Balance): регресссионный flow-matching лосс — коэффициент каждому
  оркестрационному действию через балансировку подтраекторий против **замороженной референсной** траектории.
  Плюс смешивание измеренной task-level reference reward statistics с prefix-dependent поправками.
- **Validated Skill Admission:** кандидатный навык сначала пробуется и продвигается только если парные
  доказательства проходят последовательный тест под **общим номинальным бюджетом тестирования**.
- Онлайн-самоэволюция вместо пост-хок: оркестратор чинит «правдоподобные, но провальные» шаги по признакам
  исполнения и обученной оценке значения. 12 датасетов: QA, математика, код, интерактивные решения.
- **Для нас:** (а) требование замороженного референса = детерминированный гейт «есть baseline — сравнение
  валидно, нет — результат невалиден»; (б) наш приём скиллов/конспектов стоит перевести на схему
  «проба → парные доказательства до/после → held-out-бюджет»; (в) «навык никогда не выводится из оборота» —
  наш реальный дефект: старые конспекты не ревизуются, нужна процедура снятия/ревизии, а не только добавления.
- Границы: перенос пока концептуальный (flow-matching/RL), метрик в аннотации нет, код не клонировался,
  локально ничего не запускалось.

### 2. Radware MCP Server Protection — таксономия угроз MCP
- Вендорский продукт (Apache/платный), локально не проверяем; ценность — **таксономия**:
  protocol abuse, атаки на аутентификацию, перечисление tools/resources, несанкционированные
  MCP-взаимодействия, **AI-driven tool flooding**, DoS.
- 4 блока: visibility attack surface / MCP-aware protection / governance / мониторинг активности агентов.
- Контекст: Stacklok 2026 — около половины софтверных компаний используют MCP в проде, 19% — широко.
- **Для нас:** инвентаризация MCP-серверов и экспонируемых tools — предварительный гейт (нет реестра →
  нет контроля); tool flooding — прямое продолжение темы «гейт на линии разлома».

### 3. Agent Memory Survey (arXiv 2602.06052, TMLR) — память как субстрат самоэволюции
- Таксономия по трём осям: **субстрат** (параметрическое vs внешнее retrieval-augmented) ×
  **когнитивный механизм** (сенсорная/рабочая/эпизодическая/семантическая/процедурная) ×
  **субъект** (user-centric vs agent-centric).
- Ключевой механизм: краткосрочная память **определяет, какие опыты вообще воспринимаются**,
  долгосрочная консолидирует их в переиспользуемые знания и навыки. Управление памятью — обучаемая
  способность (RL context curation, консолидация опыта в момент решения, портируемые agent skills).
- **Для нас:** наш отбор тем в учебнике (🔴→🟢 по laya) — это ровно short-term memory gating;
  конспект в KB — консолидация в долгосрочную. Значит качество «памятного отбора» ограничивает
  самообучение роя. Пробел: у нас почти нет user-centric слоя.

### 4. AWS Strands Box + Dogwood — эталон enforcement-архитектуры
- Два слоя: **containment** (OS-изоляция, macOS Seatbelt — жёсткая граница) + **policy** (Dogwood).
- Enforcement points: egress gateway, Python-интерпретатор (Monty), Shell-интерпретатор, MCP-broker.
  Интерпретаторы вынесены **за пределы** песочницы — сознательный размен: TCB шире, зато политику
  нельзя обойти изнутри агентского процесса.
- **Единая схема событий:** `fs:read` / `fs:delete` / `http:request` — независимо от инструмента.
  Правило «после чтения из customer-data — блокировать исходящие HTTP» пишется без указания инструмента.
- **Секреты:** агент получает placeholder-токен, настоящий секрет подставляет gateway — секрет не
  входит в окружение агента (Bearer / custom header / Basic / query / AWS SigV4).
- **Отказ машиночитаем:** HTTP 403 + `policy denied this operation` + `@id` + `@description` правила.
  Тонкость: лимит «3 поста за 10 мин» считает ответы 200 (привязка на `::response`), иначе отказы
  съедают лимит.
- **Противоречие «пермишены харнеса»:** харнес видит вызов инструмента, а не эффект; форматы правил
  не переносимы. Это аргумент за наш внешний enforcement-слой.
