## 3. Находки

### F2 (серьёзная, ложная приёмка — повторная) — `tests/test_p4_bench.py:247-261`
Оба бенчмарка воспроизведения дефекта (`test_bench_repro_default_addressing`, `test_bench_repro_report`)
пропускаются при **каждом** прогоне: `SKIPPED [1] tests/test_p4_bench.py:251: Hot module not available`,
`SKIPPED [1] tests/test_p4_bench.py:261`. Тесты не проверяют ничего и при этом выглядят зелёными.

**Причина (доказана живьём):** корень репозитория в этих тестах берётся как
`Path(__file__).resolve().parent.parent` = `…/Project4`, а живой горячий модуль лежит в
**`/home/thomas/LivingCode/scripts/professor_sync.py`** — на уровень выше. Живой корень проекта
LibraryCode определяется по наличию `tools/cycle_claim_gate.py` (`p4_provenance/paths.py:find_repo_root`),
и `paths.REPO_DIR` = `/home/thomas/LivingCode`. Прямая проверка:

```
repro_default_addressing(…/Project4)     -> HotModuleMissing: нет горячего модуля: …/Project4/scripts/professor_sync.py
repro_default_addressing(…/LivingCode)   -> OK: {'default_addressing': [1,2,3,4], 'addressing_is_default': True, …}
```

**Это незакрытый хвост прошлого возврата.** `[AUDIT_RETURN] Project4` от 26.10 (журнал, стр. 8023)
требовал починить именно это («тесты/test_p4_bench.py:247,258 — неверный корень репо, 2 бенчмарка repro
всегда skip вместо проверки»). Правка была закрыта не полностью: канонический вид уже есть в
`tests/test_p4_provenance.py:32-36` (после `parent.parent` идёт `if REPO.name == "Project4": REPO = REPO.parent`),
а в `test_p4_bench.py` этой поправки нет. В дереве живут **два разных канона корня** — источник дефекта.

**Починка (одна правка, 2 строки):** в `test_p4_bench.py` в обеих функциях заменить
`repo = Path(__file__).resolve().parent.parent` на живой корень — скопировать логику из
`test_p4_provenance.py` (`…parent.parent`, затем `if repo.name == "Project4": repo = repo.parent`).
