## Детали изменений

### Цикл 12512: `max_history` → ошибка с подсказкой
**Проблема:** Пользователи часто пишут `max_history` вместо правильного `history_limit`. Ключ молча игнорировался, история росла без границ.  
**Решение:** В `_validate_config` добавлена проверка: если передан `max_history` → `ValueError` с сообщением «Did you mean 'history_limit'?».  
**Тесты:** Конструктор и `update_config` оба отвергают `max_history`; `history_limit` работает.

### Цикл 12513: Жёсткая валидация `history_limit`
**Проблема:** Старый `_history_limit()` молча игнорировал `0`, `-5`, `"many"`, `True` — падал на дефолт 1000. Опечатка `history_limit: 0` отключала кап невидимо.  
**Решение:** Валидация в `_validate_config` (покрывает `__init__` и `update_config`): должен быть положительный `int`, не `bool`. `None` разрешён (означает «дефолт»).  
**Тесты:** Все плохие значения вызывают `ValueError`; `None` → дефолт; позитивные — работают.

### Цикл 12514: `get_metrics()` — симметрия с `get_config()` / `get_state()`
**Цель:** Потокобезопасное чтение метрик без полного снапшота состояния.  
**Реализация:** `with self._lock: return copy.deepcopy(self.state.metrics)`.

### Цикл 12515: `get_last_evolution_at()` — прямой доступ к маркеру
**Цель:** Маркер `last_evolution_at` был доступен только через `time_since_last_evolution()` или `get_state()`.  
**Реализация:** Возвращает `self._last_evolution_at` под замком. Не меняется при `freeze()`/`reset()` (по дизайну цикла 12353).

### Цикл 12516: Валидация записей истории при десериализации
**Проблема:** Цикл 12510 проверял только что запись — `dict`. Пустой `{}` грузился и ломал потребителей.  
**Решение:** В `SuperguardState.from_dict` проверяем обязательные ключи: `timestamp` (str), `subcycle` (int). Ключ `event` обязателен только для новых записей (после цикла 12359) — для совместимости со старыми файлами допускаем его отсутствие, но если есть — должен быть строкой.  
**Тесты:** Все комбинации невалидных записей отвергаются с именем поля и индексом; валидные грузятся; старый формат без `event` — ок.

### Цикл 12517: `state_version` в `SuperguardState.to_dict()`
**Проблема:** Версия схемы была только в конверте движка (`engine.to_dict()`). Голое состояние (без конверта) теряло версию.  
**Решение:** Добавляем `"state_version": SuperguardEngine.STATE_VERSION` в `SuperguardState.to_dict()`. В `from_dict` валидируем: будущая версия → отказ с сообщением; отсутствующая (старые файлы) → грузится.

### Цикл 12518: `reset(..., reset_evolution_marker=True)`
**Проблема:** `reset(force=True)` на замороженном движке сбрасывал `subcycle`/`metrics`, но оставлял `last_evolution_at` указывающим на старую эволюцию. Планировщик думал, что эволюция была «только что».  
**Решение:** Новый параметр `reset_evolution_marker=False` (по умолчанию сохраняет старое поведение). При `True` маркер устанавливается в время ресета.  
**Тесты:** По умолчанию маркер не меняется; с флагом — обновляется; `time_since_last_evolution()` отражает сброс.

### Цикл 12519: `time_until_next_evolution()` — секунды до следующей
**Цель:** Дополнение к `next_evolution_time()` для планировщиков/UI.  
**Реализация:** `(next_evolution_time() - now).total_seconds()`, зажимаем в `max(0.0, ...)`. Возвращает `None` если интервал не задан.

### Цикл 12520: Свойство `is_frozen`
**Цель:** Чистый API вместо `get_status() == "FROZEN"` или `engine.state.status == Status.FROZEN` (последнее ломает инкапсуляцию).  
**Реализация:** `@property def is_frozen(self) -> bool:` под замком.

### Цикл 12521: `config_schema()` — программная схема конфигурации
**Цель:** Документирование полей для тулинга, валидации, UI.  
**Реализация:** Класс-метод возвращает словарь с полями: `name`, `version`, `subcycle`, `evolution_interval`, `history_limit` — каждый с `type`, `required`, `default`, `description`.

## Архитектурные принципы (соблюдены)

1. **Потокобезопасность** — все новые методы используют `self._lock`
2. **Глубокое копирование** — `get_metrics`, `get_config`, `get_state` возвращают независимые копии
3. **Обратная совместимость** — старые файлы состояния (без `event`, без `state_version`) грузятся
4. **Чёткие ошибки** — каждое `ValueError` называет поле, индекс, полученное и ожидаемое значение
5. **Не ломаем существующее поведение по умолчанию** — новые параметры (`reset_evolution_marker`) имеют безопасные дефолты
