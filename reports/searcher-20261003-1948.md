## 4. Честное предупреждение о методе проверки

Первый тест дал **ложный вердикт «песочница не работает»**: команда `ls ~/.ssh`
успешно показала имена файлов (`id_ed25519_cathedral`, `totomoto_ed25519`…), хотя
`denyRead: ["~/.ssh/**"]` в конфиге есть.

Проверка содержимого показала настоящую картину: `head -c 60 ~/.ssh/id_ed25519_cathedral`
→ `Permission denied`. **Landlock запрещает чтение содержимого, но каталог остаётся
видимым для перечисления.**

Вывод для будущих слотов: изоляцию проверять **реальным чтением данных**. Проверка
по выводу `ls` даёт ложный вердикт в обе стороны — и снимет тревогу, и вынесет
ложное «всё хорошо»/«всё плохо». Ошибка зафиксирована в Учебнике и в извещении агентам.

## 5. Почему не landrun / sandlock / greywall

| Инструмент | Причина отказа |
|---|---|
| **landrun** (2312★) | Требует Landlock **ABI v9**, у нас **v8** → `permission denied`. Проверено напрямую. Задача закрыта — не тратить слот |
| **sandlock** (541★, arXiv 2605.26298) | Правильный кандидат по ABI (нужен v6+), но **готовых бинарей нет** — только `cargo build` из исходников → нужен `git clone`, блокируется |
| **greywall** (306★) | `go install` не запускает цель `download-tun2socks` → embed-пустая (`tun2socks_embed.go:13`), обход упирается в read-only кэш Go-модулей. Готовых бинарей нет |
| **fence** (986★) | **Работает.** Есть готовый релиз x86_64 → clone не нужен. Не требует ABI v9 |

## 6. Ограничения (честно, не выдаю за полноту)

1. **Local loopback не пробрасывается.** `localhost`/`127.0.0.1` изнутри песочницы —
   это песочница, не хост. Локальные ollama/lemonade так **не достаются** без явного
   `-p <порт>`. Существенно для кодеров, гоняющих локальные модели.
2. **eBPF-монитор fence не работает без root** — в списке LSM нет `bpf`. Изоляция
   действует, наблюдение за нарушениями сведено к прокси-логу `--fence-log-file`.
   Seccomp user notification работает — listener-фильтр ставится, argv применяется.
3. **Landlock не режет листинг каталогов** (см. п. 4).
4. Предупреждение `runtime exec deny warning ... coreutils/chroot` — безвредный шум.

## 10. Вторая часть слота: проброс портов + найденный сломанный шим

Поскольку время оставалось, проверил самое вероятное практическое препятствие —
доступ кодеров к локальным моделям из песочницы.

**Ограничение снято.** Механизм найден в [docs/configuration.md](https://github.com/fencesandbox/fence/blob/main/docs/configuration.md):
`network.allowLocalOutbound: true` + `network.allowLocalOutboundPorts: [порты]`,
мост на socat (`/usr/bin/socat` уже установлен). Ключ работает **только на Linux** —
на macOS список портов игнорируется.

Добавлено в профиль: `allowLocalOutboundPorts: [11434, 8792]`.

Живая проверка:
| Проверка | Факт |
|---|---|
| `127.0.0.1:11434` из песочницы | `502` + тело `{"error": "<urlopen error [Errno 111] Connection refused>"}` — **побайтово совпадает с хостовым** ✅ |
| `127.0.0.1:6379` (не в списке) | `000` — заблокирован ✅ |

Сверял **тело ответа**, а не только HTTP-код: иначе «502» не отличить от заглушки
песочницы.

**Найденная попутно поломка (нужно решение Владыки).** Порт 11434 занят не ollama,
а шимом:
```
python3 /home/thomas/LivingCode/tools/ollama_shim.py --upstream http://127.0.0.1:8792 --port 11434
```
Upstream **8792 не слушается** (`ss -ltn` пусто, curl → `000`), и `ollama` в системе
**не установлен**. Итог: локальный инференс на машине нерабочий, на 11434 отвечает
шим, проксирующий в пустоту.

Побочная ценность: именно проброс порта дал диагностический доступ — из песочницы
видно «сервис жив, отвечает 502», то есть цепочка работает до конца. Без проброса агент
увидел бы просто «порт недоступен» и не отличил бы поломку сервиса от блокировки.
