## Что считается мусором

Запись отбрасывается, если хотя бы одно условие:
- `topic` пуст или равен `"Unknown"`;
- `summary` пуст или состоит только из пробелов.

Мусор в данных — это ровно 3 записи `topic="Unknown"`, `summary=""` в каждом
из двух файлов (всего 6).

в первой строке файла и разбор кросс-файловых пересечений.

## Состояние готовности

- `load()` переживает инъекцию строки-маркера в начало JSON (реальный класс
  дефекта этого проекта — файлы ломались о `# HOT`).
- `validate()` перечисляет конкретные файлы, индексы и причины.
- `dedupe` по умолчанию dry-run; `--fix` пишет атомарно (write-to-tmp +
  `os.replace`) и оставляет `.bak`.
- `chronicle` пишет append-only запись через временный файл и `os.replace`.
- `doctor` находит повреждённые источники, `provenance` разбирает происхождение.
- CLI `python3 -m p1_memory report|validate|dedupe|chronicle|doctor|
  provenance` с JSON-выводом и exit-кодами.
- `report --check` машинно сверяет этот файл с живым прогоном: exit 0 — все
  числа совпали, exit 1 — перечислены расхождения (`--json` даёт список).
