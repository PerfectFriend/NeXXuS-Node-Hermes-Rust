## Находка 1 — источник мусора в данных (главная)

`scripts/professor_sync.py:105-116`, метод `_create_insight`:

```python
topic=data.get("topic", "Unknown"),
summary=data.get("summary", "")[:500],
relevance_score=data.get("relevance_score", 0.7),
applicable_projects=data.get("applicable_projects", [1,2,3,4]),
```

Любой вход без `topic`/`summary` молча превращается в полноценную запись
`topic="Unknown"`, `summary=""`. Именно эти 6 записей (по 3 в каждом из двух
файлов Project1) и составляют весь «мусор» — 6 из 190. Профессор не ломает
данные, он их **создаёт** по умолчанию. Пока это так, очистка памяти — сизифов

Вывод для Владыки: предложить фильтр `_create_insight` → возвращать `None`
при пустых `topic`/`summary` и выбрасывать такие записи в `load_textbook_insights`
(счётчик в отчёте). Одно слово по смыслу, но меняет объём памяти всех 4 проектов.

## Находка 5 — имя файла `{cycle:03d}`

`professor_sync.py:131`: `professor_insights_cycle_{self.cycle:03d}.json`.
Формат рассчитан на 3 цифры; при cycle ≥ 1000 (`1351`) получаем 4-значное имя —
это и есть источник `professor_insights_cycle_1351.json` рядом с
`professor_insights_cycle_001.json`. Не баг, но и не замысел: порядок имён
в алфавитной сортировке больше не совпадает с порядком циклов. Если появится
индексация по имени файла — будет ошибка. Риск низкий, отмечено для протокола.
