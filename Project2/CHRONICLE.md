Сделано по пунктам 1–11 плана:

- **Пакет и загрузка.** `loader.py` снимает строки-маркеры `# HOT`/`# COLD` перед
  разбором JSON (такой дефект ломал эти файлы ранее), сортирует файлы по номеру
  цикла, отдаёт `iter_insights()` с сервисными полями `_index`/`_file`/`_cycle`.
- **Валидация.** `validate.py`: 10 обязательных полей, типы, `relevance_score` 0..1
  (булев тип отвергнут), непустой `topic`, `applicable_projects` ⊆ {1,2,3,4},
  согласованность `total_insights` с `len(insights)`. На штатных данных замечаний нет.
- **Дедуп и мусор.** `clean_insights()` по `(topic, source_url)`. Мусор на диске:
  6 записей с `topic == "Unknown"`. `--fix` обязателен для записи, по умолчанию dry-run.
- **Атомарная запись.** `atomic_write()` — сериализация во временный файл, затем
  `os.replace`, с бэкапом `.bak`. Проверено тестом: при падении сериализации
  известные-good данные на диске не меняются, `.tmp`-мусора не остаётся.
- **Граф.** `graph.py`: узел = инсайт, пять типов рёбер, дедупликация пар.

### Пункт 19: `freshness --fix` — разметка, а не удаление

Реализовано в `p2_graph/provenance.py` три функции и в CLI флаг `--fix`:

- `stale_duplicates(files)` — записи, представимые записью из файла с более

- `apply_freshness_fix(data, plan)` — разметка глубокой копии; загруженный

Два решения против самообмана, которые стоили больше кода, чем сам `--fix`:

1. **Уже помеченные записи не считаются потерями.** Пока метка была бы
