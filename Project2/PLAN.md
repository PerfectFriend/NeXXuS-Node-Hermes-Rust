## Что такое Project2 (установлено разведкой 2026-10-03 04:0x)

Project2 — «проект-приёмник памяти Профессора», родственник Project1. Собственного кода не имеет:
- `memory/professor_insights_cycle_001.json` — 102 инсайта;
- `memory/professor_insights_cycle_1351.json` — 88 инсайтов;
- `CHRONICLE.md` — дамп синхронизации.

Фактические дефекты данных, измеренные на диске (не на глаз):
- по 3 записи с `topic == "Unknown"` в каждом файле, 2–3 с пустым `summary`;
- по 2 дубликата `(topic, source_url)` в каждом файле;
- по 3 записи без `source_url`;
- все 184 инсайта — темы **графовой инженерии** (Graph Engineering, Graphthulhu/Engraph,
  Dataview, Canvas, Obsidian-плагины, семантическая сеть vault, MCP, память агентов).
  То есть корпус Project2 — это знание о графах, и граф здесь не метафора.

Отличие от Project1 (пакет `p1_memory`): Project1 закрыл загрузку/валидацию/дедуп.
**Project2 строит поверх корпуса граф знаний** — рёбра, метрики, центральность, поиск.

## Пункты плана

1. [ ] **Создать PLAN.md Project2** с 8–12 проверяемыми пунктами эволюции.
   *Проверка:* файл существует, каждый пункт имеет строку «Проверка».
2. [ ] **Пакет `p2_graph`**: загрузка памяти, устойчивая к строке-маркеру `# HOT`/`# COLD`
   в начале файла (реальный класс дефекта, ломавший JSON этих файлов ранее).
   *Проверка:* `load_all()` на каталоге с файлом, у которого первая строка — `# HOT`,
   возвращает данные, а не исключение.
3. [ ] **Валидатор схемы инсайта**: обязательные поля, типы, `relevance_score` 0..1,
   непустой `topic`, `applicable_projects` ⊆ {1,2,3,4}, согласованность
   `total_insights` с `len(insights)`. *Проверка:* отчёт перечисляет файл/индекс/причину.
4. [ ] **Дедупликация и фильтрация мусора** по `(topic, source_url)`, dry-run по умолчанию.
   *Проверка:* на текущих данных dry-run показывает ровно 4 дубля и 6 мусорных записей.
5. [ ] **Построение графа знаний**: узел = инсайт, рёбра четырёх типов
   (`same_source`, `same_topic`, `shares_tag`, `same_category`) с дедупликацией пар.
   *Проверка:* `build_graph()` возвращает `nodes`, `edges`, `isolated`; сумма степеней
   равна `2 * len(edges)`.
6. [ ] **Метрики графа**: число узлов/рёбер, плотность, изолированные узлы, связные
   компоненты ( communities ). *Проверка:* разбор связности на artificial-графе из
   двух треугольников даёт ровно 2 компоненты.
7. [ ] **Центральность**: топ инсайтов по степени с учётом `relevance_score`.
   *Проверка:* искусственный граф «звезда» ставит центр первым.
8. [ ] **Поиск по корпусу** (`query`): подстрока по topic/summary/tags/source_url,
   ранжирование по совпадению + релевантности. *Проверка:* запрос `graph` на штатных
   данных возвращает ненулевой результат, запрос бессмысленный — пустой.
9. [ ] **CLI** `python3 -m p2_graph report|validate|graph|query --json` с exit-кодами.
   *Проверка:* `report` печатает сводку, `--json` даёт валидный JSON, exit 0.
10. [ ] **Атомарная запись** memory-файлов при `--fix` (write-to-tmp + `os.replace`)
    с бэкапом исходника. *Проверка:* тест на отсутствие `.tmp`-мусора и наличие `.bak`.
11. [ ] **Тесты unittest** (≥20) на загрузку/валидацию/дедуп/граф/метрики/поиск/CLI —
    зелёные на штатных и на искусственно испорченных данных.
    *Проверка:* `python3 -m unittest discover -s tests -v` → OK.
12. [ ] **`GRAPH_REPORT.md`** — реальные числа графа Project2, сгенерированные кодом.
    *Проверка:* числа отчёта совпадают с прогоном `python3 -m p2_graph graph --json`.
