## Фаза 6. Молчаливая потеря кратности

Ключ дедупликации — не идентификатор записи, а признак совпадения:
одна и та же пара «тема + категория + URL» может встречаться в цикле
несколько раз. Код, складывающий записи в `dict[key] = record`, теряет
лишние экземпляры молча, и числа перестают сходиться с числом записей.

- [x] **35. Дифф сохраняет кратность; равенства сходимости проверяются
      на живых циклах.** Сравнение ведётся как мультимножество; избыток
      сверх меньшей кратности попадает в `added`/`removed`, лишние
      старые экземпляры проверяются на переезд, а не объявляются
      пропажей. Обязательные равенства: `removed + moved + shared ==
      from_records` и `added + moved + shared == to_records`.
      Проверка: тест на штатном корпусе сверяет оба равенства и
      независимый пересчёт по `Counter`, а не множеству.
      Сделано: `diff.group_by_key()` (по ключу список, попарное
      сравнение), `_is_moved()` принимает итерируемое (переезд ищется
      по всем новым записям). Сбой найден пробой сходимости: из 102
      записей 001 в расчёт попадало 101, из 88 — 86. Ключ
      `unknown|ai engineering|` встречается дважды в 001 и трижды в
      1351; старые 85 перезаписей были артефактом затирания, честное
      число 86 подтверждено `tools/probe_shared_86.py`. Живой прогон:
      shared 86, added 2, removed 16, moved 0; оба равенства сходятся.
      `report --check` зелёный после перегенерации отчёта.
