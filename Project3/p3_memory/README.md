# p3_memory — память Project3 под контролем

Project3 — приёмник памяти Профессора: файлы
`memory/professor_insights_cycle_*.json` приходят из синхронизатора
(`scripts/professor_sync.py`) и сразу попадают в архивы всех четырёх
проектов. Пакет `p3_memory` читает эти файлы, сводит их в канонический
корпус и отвечает на вопросы, на которые сам корпус отвечать не умеет:
сколько здесь записей на самом деле, откуда каждая пришла, что изменилось
между циклами и совпадает ли содержимое с соседними проектами.

## Быстрый старт

```bash
cd Project3
python3 -m p3_memory validate          # схема всех memory-файлов
python3 -m p3_memory metrics           # сколько записей и как они распределены
python3 -m p3_memory search agent      # поиск с происхождением каждой строки
python3 -m p3_memory diff              # что изменилось между двумя последними циклами
```

Добавьте `--json` к любой команде — вывод станет машинно-читаемым. Общие
опции (`--memory-dir`, `--json`, `--limit`) работают и до имени команды,
и после него.

## Команды

| Команда | Что делает | Пишет на диск |
|---|---|---|
| `validate` | проверяет схему всех memory-файлов, снимая маркеры `# HOT`/`# COLD` | нет |
| `load` | читает один memory-файл со снятием маркеров | нет |
| `identity` | сравнивает тело Project3 с Project1/2/4 (содержание и байты отдельно) | нет |
| `distinct` | записи Project3, которых нет ни у одного соседа | нет |
| `audit` | аудит адресации `applicable_projects` (дефект синхронизатора) | нет |
| `metrics` | метрики канонического корпуса | нет |
| `search` | поиск с ранжированием, фильтрами и происхождением записи | нет |
| `report` | печатает `DUPLICITY_REPORT.md`; `--fix` пишет, `--check` сверяет свежесть | только с `--fix` |
| `canon` | канонический корпус в JSON; `--fix` пишет | только с `--fix` |
| `chronicle` | дописывает раздел в `CHRONICLE.md`; `--check` только аудит | только без `--check` и с `--title` |
| `gate` | машинные факты (прогон тестов, реестр дефектов) для `tools/cycle_claim_gate.py` | только с `--write` |
| `registry` | реестр дефектов Project3 и сверка заявления агента | только с `--write` |
| `honesty` | сквозная проверка: строит эталонное заявление из фактов и ловит ложное | только с `--write` |
| `cycles` | покрытие циклов: файлы, числа записей, разрывы нумерации | нет |
| `diff` | дифф двух циклов: пять видов перехода (удалено / переехало / добавлено / изменено / перезаписано) с перечнем записей; при нарушении сходимости печатает ВНИМАНИЕ | нет |

## Коды возврата

- `0` — успех, либо честный отказ-пустой результат (`search` без находок).
- `1` — проверка не прошла: `report --check` на устаревшем артефакте,
  `chronicle --check` на файле с претензиями, `gate`/`honesty` при расхождении
  заявления с фактами.
- `2` — ошибка использования: неизвестная команда, отказ писать вне проекта.

## Инварианты

1. **Ничего не пишется без `--fix`.** `report` и `canon` без `--fix` только
   печатают; `report --check` и `chronicle --check` не пишут вообще ничего.
2. **Все пути внутри проекта.** `safe_path()` отвергает `..` и абсолютные
   пути, поэтому запись в `../Project4` невозможна (код 2).
3. **Запись атомарна и с бэкапом.** Пишется временный файл, затем
   `os.replace`; предыдущая версия уходит в `.bak` — при сбое известный
   хороший файл остаётся целым.
4. **Маркеры не ломают данные.** Файл, испорченный `# HOT` в первой строке,
   читается: маркер снимается, JSON валиден.
5. **Числа отчёта не зашиты.** `DUPLICITY_REPORT.md` порождается кодом;
   `report --check` падает (код 1), если файл на диске разошёлся с тем, что
   посчитал бы код сейчас.

## Известные открытые дефекты

Их не два, а полтора: дефект адресации в чужом hot-коде синхронизатора
(`scripts/professor_sync.py:113`) и немаркированная граница памяти у
Project2. Полный список с владельцами — `defect_registry.json`, краткая
выжимка — в разделе 8 `DUPLICITY_REPORT.md`. Пока дефекты открыты,
`tools/cycle_claim_gate.py` возвращает код 2 на любом заявлении о закрытии
цикла: закрыть цикл честно нельзя.

## Тесты

```bash
python3 -m pytest tests/ -q          # весь набор
python3 -m p3_memory honesty         # доказать, что гейт ловит ложь
```

## Структура

- `loader.py` — чтение файлов, снятие маркеров, валидация схемы.
- `canon.py` — канонизация корпуса, дедуп по ключу «тема + категория + URL».
- `identity.py` — сравнение с соседними проектами, природа расхождений.
- `attribution.py` — чьи это инсайты на самом деле (без `applicable_projects`).
- `metrics.py` — метрики и поиск с ранжированием.
- `diff.py` — дифф циклов и покрытие по циклам.
- `gate.py` — факты для `tools/cycle_claim_gate.py`.
- `report.py` — порождение `DUPLICITY_REPORT.md` и его свежесть.
- `paths.py` — границы проекта, атомарная запись, аудит `CHRONICLE.md`.
