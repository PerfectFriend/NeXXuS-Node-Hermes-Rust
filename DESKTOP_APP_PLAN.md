# План разработки десктоп-приложения + монитора ноды NeXXus

**Версия:** 0.1.0  
**Дата:** 03 ноября 2026 г.  
**Целевой проект:** NeXXus-Node (github.com/PerfectFriend/NeXXus-Node)  
**Статус:** Черновик плана (предварительный)

---

## 1. Обзор и цели

Создать десктоп-приложение для управления и мониторинга узла NeXXus (`nexxusd`) с:

- **Системным треем** — иконка в области уведомлений ОС, контекстное меню, быстрые действия.
- **Главным оконным десктопом** — полноценный дашборд монитора ноды с панелями состояния, сетевой активностью, хранилищем чанков, SMP-сообщениями,_epoch_-историей, Tor-статусом.
- **Локальным IPC** — связь с запущенным `nexxusd` через TCP/WS или встроенный локальный API.
- **Кроссплатформенность** — Windows, Linux, macOS (для старта: Windows + Linux).

---

## 2. Стек технологий и обоснование

| Слой | Технология | Обоснование |
|------|------------|-------------|
| **Backend** | Rust + Tauri 2.x | Естественное продолжение существующего Rust-кода (`nexxus-core`, `nexxus-node`). Tauri даёт нативный веб-фронтенд с Rust-бэкендом, малый размер бинарника, нет Chromium-памяти (в отличие от Electron). |
| **Frontend** | HTML/CSS/JS (Vanilla или Vue 3) + Tailwind CSS | Минимальные зависимости, быстрота разработки, полный контроль над UI. Tailwind даёт современный вид без писать CSS вручную. |
| **Язык бэкенда** | Rust (edition 2021) | Переиспользует существующие крите: `nexxus-core` (криптография, wire, SMP, Epoch), `nexxus-node` (сеть, хранилище). |
| **IPC с nexxusd** | Локальный TCP/WS на `127.0.0.1` или встроенный узел в бэкенде Tauri | Два варианта: (a) отдельный процесс `nexxusd` + клиентский подключающийся к нему; (b) встроенный `nexxusd` как библиотека внутри Tauri-бэкенда. |
| **Системный трей** | `tao::tray` (встроено в Tauri) | Нативный трей для Windows/Linux/macOS без внешних зависимостей. |
| **Сборка** | `cargo-tauri` + `cargo` | Стандартная цепочка сборки Tauri. |

**Альтернатива (отложена):** Flutter Desktop (уже есть опыт в проекте CatVanGoghFlutter). Может быть рассмотрена как второй вариант, если Tauri покажет ограничения в трее/нативных виджетах.

### 3.1 Варианты связи с nexxusd

**Вариант A (рекомендуемый для MVP):** `nexxusd` запускается отдельным процессом. Десктоп-приложение подключается к нему по локальному TCP/WS порту (например, `127.0.0.1:4010`). Бэкенд Tauri держит постоянное соединение и пересылает события на фронтенд через Tauri events.

**Вариант B:** `nexxusd` компилируется как библиотека и встраивается в Tauri-бэкенд. Нет отдельного процесса, но сложнее изоляция и перезапуск.

**Решение MVP:** Вариант A — проще отлаживать, не требует изменений в `nexxusd` (добавить только локальный API эндпоинт для мониторинга).

### 5.1 Общая компоновка

```

├──────────┬──────────────────────────────────────────────────┤
│          │                                                   │
│  Сайдбар │  Главная панель (дашборд)                         │
│          │                                                   │
│  ● Дашборд│  ┌─────────────┐ ┌─────────────┐ ┌──────────┐ │
│  ● Узел   │  │ Статус узла │ │ Сетевые пиры│ │ Хранилище│ │
│  ● Пиры   │  │             │ │             │ │          │ │
│  ● SMP    │  │ NodeId      │ │ Подключено  │ │ Чанков   │ │
│  ● Epoch  │  │ Онлайн      │ │ N           │ │ N        │ │
│  ● Tor    │  │ Адрес       │ │ Тор: вкл/вык│ │ Использ. │ │

│          │                                                   │
│          │  ┌─────────────────────────────────────────────┐ │
│          │  │ Лог активности (последние события)          │ │
│          │  │                                             │ │
│          │  └─────────────────────────────────────────────┘ │
│          │                                                   │
└──────────┴──────────────────────────────────────────────────┘
```

### 5.2 Панели и виджеты

#### 5.2.1 Статус узла (Overview)
- NodeId (hex, копирование в буфер)
- Версия приложения и версии crates
- Адрес прослушивания (IP:ポート)
- Статус: Онлайн / Оффлайн / Синхронизация / Ошибка
- Время работы (uptime)
- Количество подключений (входящих/исходящих)
- Кнопка: Перезапуск узла, Пауза, Открыть логи

#### 5.2.2 Сетевые пиры
- Таблица пиров: NodeId, адрес, порт, время подключения, направление (вх./исх.), протокол (TCP/Ws/Tor)
- Статус подключения: Подключен / Отключен / Бан
- Кнопки: Добавить пир вручную, Удалить пир, Обновить список
- Kademlia-диаграмма (опционально): визуализация ближайших соседей по XOR-дистанции

#### 5.2.3 Хранилище чанков
- Всего чанков, использовано места (ГБ), свободно места
- Размер чанка: 16 KiB
- Reed-Solomon 4+2: данные/паритети shards
- Кнопка: Открыть папку хранилища, Очистить кэш, Экспортировать список чанков
- График заполнения диска во времени

#### 5.2.4 SMP-сообщения (Secure Message Protocol)
- Список исходящих/входящих SMP-конвертов
- Статус: Отправлен / Доставлен / Ошибка / В ожидании
- Получатель (NodeId), размер payload, временная метка
- Кнопка: Отправить тестовое SMP-сообщение, Посмотреть содержимое (декрипт)

#### 5.2.5 Epoch Finalize (Committee Multi-Sig)
- Текущий номер эпохи
- Merkle Root (hex)
- Total bytes
- Подписи аудиторов: N из M
- Статус кворума: Достигнут / Не достигнут
- Последняя подписанная эпоха

#### 5.2.6 Tor-статус
- Включен / Выключен
- Onion v3 адрес (если доступен)
- Статус подключения к Tor-сети
- Активные onion-соединения
- Кнопка: Включить Tor, Открыть onion-адрес в браузере

#### 5.2.7 Лог активности
- Поток событий в реальном времени: подключения пиров, сохранение чанков, SMP-доставка, EpochFinalize, ошибки
- Уровни: INFO, WARN, ERROR
- Поиск и фильтрация по уровню
- Экспорт лога в файл

## 6. Взаимодействие с nexxusd (IPC)

### 6.1 Протокол

Локальный WebSocket на `ws://127.0.0.1:4010` (или TCP с length-delimited frames, совместимый с wire v3).

Сообщения от приложения к ноде:
- `get_status` → статус узла
- `get_peers` → список пиров
- `get_chunks` → статистика хранилища
- `get_smp_messages` → история SMP
- `get_epoch_status` → статус текущей эпохи
- `get_tor_status` → статус Tor
- `send_smp_envelope` → отправить SMP-конверт
- `pause_node` / `resume_node` / `restart_node` → управление нодой

Сообщения от ноды к приложению (push-события):
- `peer_connected` / `peer_disconnected`
- `chunk_stored` / `chunk_fetched`
- `smp_envelope_received` / `smp_envelope_sent`
- `epoch_finalized`
- `tor_status_changed`
- `error`

### 6.2 Бэкенд Tauri commands

| Команда | Описание |
|---------|----------|
| `node_status` | Получить статус узла |
| `node_peers` | Список пиров |
| `node_chunks` | Статистика чанков |
| `node_smp` | История SMP |
| `node_epoch` | Статус эпохи |
| `node_tor` | Статус Tor |
| `node_pause` | Пауза ноды |
| `node_resume` | Возобновить ноду |
| `node_restart` | Перезапуск ноды |
| `tray_toggle_window` | Показать/скрыть главное окно |
| `settings_save` | Сохранить настройки |
| `settings_load` | Загрузить настройки |
