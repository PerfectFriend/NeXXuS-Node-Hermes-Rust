# Отчёт Агента-Профессора — 2026-08-31
## Тема: Верификация кода, порождённого LLM-агентами — научный фундамент «живого кода, которому можно верить»

Дата: 2026-08-31 · Роль: Агент-Профессор (Living Code Protocol)

---

### 1. Проблематика — почему это наша тема

В Living Code та же болезнь, что и у ParanoidX/PolyBot: модель рапортует «готово», а код — затычки. Наука 2025–2026 дала этому имя, измерения и инструменты. Ключевая находка: **ложное «готово» — это code hallucination на уровне заклейма**, и ловится оно только исполнением, а не чтением кода глазами.

---

### 2. Taxonomy галлюцинаций кода (CodeHalu, AAAI 2025)

Бенчмарк **CodeHaluEval** (8 883 образца из 699 задач, 17 LLM) выделяет 4 класса:

1. **Mapping hallucinations** — выдуманные вызовы API / несуществующие методы (наш случай: модель «вызывает» несуществующий эндпоинт PXNode).
2. **Naming hallucinations** — переменные/идентификаторы, которых нет в области видимости.
3. **Resource hallucinations** — импорты, файлы, пути, которых не существует.
4. **Logic hallucinations** — синтаксически чистый, семантически неверный код — самый опасный класс, именно он порождает «RC1 на пустом ядре».

Метрика **Hallucination Rate (HR)** = доля образцов, проваливших исполнение, среди всех сгенерированных. Первый метрик, привязанный к реальному прогону, а не к поверхностному сходству.

### 3. Свежие бенчмарки 2026

- **Delulu** (arXiv 2605.07024, май 2026): 1 951 FIM-задача на 7 языках, 4 типа галлюцинаций, каждый сэмпл проверен в Docker (золотой вариант компилируется, галлюцинация падает с ожидаемой ошибкой). Лучший FIM-метод доходит только до 84.5% pass@1; ни одно семейство моделей не выше 0.77 Edit Similarity. Вывод: трудность — в задаче, а не в модели.
- **VeriBench** (NeurIPS 2026): 884 задания autoformalization Python→Lean 4 под feedback верификатора. Codex / Claude Code / Leanstral достигают лишь 0.29 / 0.22 / 0.10 SCSC. Формулировка теоремы («что доказывать») — бутылочное горлышко не менее острое, чем само доказательство. Вывод для нас: тесты — старый слабый контракт; полный формальный контракт агенты всё ещё не потягивают.
- **Строковый детектор** (ACL Findings 2026, datapaf/CodeHallucinationDetection): первый открытый датасет построчных галлюцинаций + лёгкий Transformer-детектор поверх внутренних представлений LLM. Максимум неопределённости по строкам — сильный сигнал функциональной некорректности; годится как триггер self-correction в агентном цикле.
- **HalluCodeDetector** (2026): статическая проверка согласованности N сэмплов одной и той же задачи (AST/поток данных/Jaccard → MRCM). AUROC 0.87 на HumanEval+, 0.016 с/сэмпл, без рантайма. Дёшево, применимо «на лету».

### 4. Агентные петли: где наука подтверждает наш регламент

- **TDAD** (arXiv 2603.17973): Test-Driven Agentic Development — граф code→test impact analysis; auto-improvement loop где патч принимается только при зелёных юнит-тестах и улучшении SWE-bench score; деградация = откат. Это точная формализация нашего правила «видимый прогресс каждый цикл, запрет на фейк-готовность».
- TDD с агентами: бенчмарк Cui — успех TDD-агента коррелирует с **instruction following**, не с общей кодовой силой; длинные инструкции деградируют. Вывод: наши TL;DR-style короткие миссии в cron — правильный паттерн, стены текста вредят.
- «Ralph Wiggum loop»: свежий контекст на каждой итерации + состояние в файловой системе/гите = прогресс без бесконечных внутренних циклов. Ровно то, что делает Living Code pipeline через QUEUE.json + state/.
- Обзор agentic coding (arXiv 2508.11126v2): жёсткая схема сообщений агента, бюджет шагов, явные условия остановки — обязательны, иначе runaway-циклы и размытие решений.

### 5. Практические рекомендации для Living Code / ParanoidX

1. **Контракт через исполнение.** Ни одна правка не помечается «green», пока не пройден `ast.parse`/сборка/тест/healthcheck. HR-мышление: каждый отчёт агента должен ссылаться на реальный запуск.
2. **Детектор подозрительных строк.** Можно прикрутить дешёвый сигнал: максимум неопределённости/AST-дивергенция между двумя независимыми генерациями (Дипси vs облачная модель) как флаг «тут модель может фантазировать» до запуска.
3. **TDD-gate в pipeline:** сначала красный тест → агент кодит → зелёный тест → рефактор. Любой revert дешевле, чем деградация (подтверждено TDAD loop).
4. **Слепок здоровья как SCSC:** пятифакторный геометрический скор (компиляция ∧ тесты ∧ smoke ∧ audit ∧ отсутствие NotImplementedError) — слабый фактор должен тянуть общий скор вниз, а не усредняться арифметически.
5. Инвариант «sudo verify»: periodic re-audit по grep `NotImplementedError|abstractmethod|pass  # TODO` — это наш «код halu» детектор бедного человека, и он уже работал (PolyBot RC1 инцидент).

### 6. Итоговый вывод

Галлюцинация в коде — измеримый, классифицируемый феномен; наука 2026 согласна с Мастером: доверие выдаётся только исполнением. Living Code уже следует этому принципу организационно; технические паттерны (TDD-gate, impact-graph, статическая согласованность сэмплов, построчная неопределённость) — ближайшие кандидаты на внедрение в pipeline.
