## Детальная процедура аудита проекта

Для каждого проекта аудит включает следующие шаги:

### Шаг 1: Анализ журнала
- Прочитать `/home/thomas/LivingCode/agents/journal.md`
- Записать своё имя и отчество в журнал при первом запуске
- Найти наиболее recently modified проект

### Шаг 2: Identify changed files
- Использовать `git diff` для выявления недавних изменений
- Проанализировать изменённые файлы (.js, .py, .md, etc.)

### Шаг 3: Review hot code
- Проверить изменённые файлы на соответствие требованиям
- Выполнить статический анализ кода
- Проверить отсутствие опасных паттернов (eval, exec, hardcoded secrets)

### Шаг 4: Security audit
- Проверить на наличие уязвимостей:
  - Нет `eval()` или `exec()` вызовов
  - Нет хардкода API ключей, секретов, паролей
  - Нет шаблонов shell инъекций
  - Нет шаблонов SQL инъекций
  - Нет уязвимостей path traversal

### Шаг 5: Test verification
- Запустить существующие тесты для проекта
- При отсутствии тестов - создать базовые проверочные скрипты
- Убедиться, что все тесты проходят

### Шаг 6: Documentation review
- Проверить наличие и актуальность README.md
- Проверить наличие архитектурной документации
- Убедиться, что изменённые функции документированы

### Шаг 7: Performance check (если применимо)
- Для игровых движков - проверить производительность核心 функций
- Для веб-приложений - проверить время загрузки и отзывчивость

### Шаг 8: Formulate recommendations
- Дать конкретные рекомендации по улучшению кода
- Указать на потенциальные проблемы
- Подтвердить, что код готов к слиянию/релизу

### Шаг 9: Create report
- Составить детальный отчёт в формате Markdown
- Включить все выявленные проблемы и рекомендации
- Сохранить в `/home/thomas/LivingCode/reports/` с соответствующим именем

### Шаг 10: Report delivery and triggering
- Отправить отчёт Инквизитору через `hermes send --to telegram:-1004431090317:252 "MEDIA:/path/to/report.md"`
- Оставить заметку в журнале о проделанной работе
- Записать триггер Владыки: "[TRIGGER_LORD] lord-of-code"
