# ADR-0003: Reed-Solomon — собственная реализация GF(2⁸)

**Статус:** Принят, 2026-11-02.

## Контекст
`nexxus-vectors/03_reed_solomon_gf256.json` задаёт конкретную матрицу: P1 = XOR всех 4 data-шардов (коэффициенты [1,1,1,1]), P2 = Vandermonde [1,2,4,8], полином `0x11D`. Сторонние RS-крейты (`reed-solomon-simd`) используют свою генераторную матрицу и не совпадут побайтово.

## Решение
Собственный модуль `crates/nexxus-core/src/rs/`:
- `gf256.rs` — exp/log таблицы, mul/div/inv над GF(2⁸), poly `0x11D`.
- `matrix.rs` — Gauss-Jordan инверсия 4×4 с кэшем на все `C(6,4)=15` комбинаций выживших шардов.
- `mod.rs` — `encode(&[u8]) -> [Shard;6]`, `decode(&[Shard], original_len)`.

Единственный источник истины — golden-вектор. Тест обязан совпасть хешами всех 6 шардов и первыми 16 байтами каждого.

## Последствия
`reed-solomon-simd` допускается только как второй бэкенд в бенчмарке для сравнения скорости, никогда как эталон корректности.
