# ADR-0001: Wire Protocol v3 — бинарные payload'ы + подпись кадра

**Статус:** Принят, 2026-11-02.

## Контекст
`PROTOCOL_WIRE_SPEC.md` требует строго бинарные payload'ы; TS-код шлёт JSON (`encodeJsonPayload`, `encodeStoreChunk` с JSON-заголовком). Кадр защищён только SHA-256 чексуммой — аутентификации отправителя нет. Таблица опкодов расходится со спекой (см. ADR-0002).

## Решение
Канонический кадр **v3** (`version = 0x03`), Big-Endian без исключений:

```
[0..3]    Magic "NEXX"        4B
[4]       Version 0x03        1B
[5]       Opcode              1B
[6..9]    RequestId u32_be    4B
[10..13]  PayloadLength u32   4B
[14..45]  Checksum SHA-256    32B   (opcode||req_id||len||payload)
[46..109] Signature Ed25519   64B   (opcode||req_id||len||payload||session_nonce)
[110..N]  Payload             переменная, СТРОГО бинарный по §4 спеки
```

- Заголовок v3 = **110 байт**. Подпись — над теми же полями, что и чексумма, плюс `session_nonce` (32B, из handshake) против replay.
- `session_nonce` согласуется при WS-handshake: обе стороны обмениваются NODE_ANNOUNCE с nonce до обмена полезными кадрами.
- Узел на v2 получает `ERROR_RESPONSE` с кодом `0x0003 ERR_VERSION_UNSUPPORTED`. Окно параллельной поддержки — один релиз.

## Последствия
- JSON-payload'ы (`encodeJsonPayload`) уходят из wire-слоя полностью; остаются только в HTTP API демона (для панели).
- Добавляется код ошибки `0x0007 ERR_UNAUTHORIZED` (битая/отсутствующая подпись) — правка спеки.
