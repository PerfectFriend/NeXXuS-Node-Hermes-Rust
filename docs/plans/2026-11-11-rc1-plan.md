# NeXXus RC1 — план эволюции (от ревизии 11.11.2026)

> База: `docs/audits/2026-11-11-rc1-readiness-review.md` + план v3 (`docs/plans/2026-11-09-nexxus-evolution-v3.md`).
> **RC1 = первый релиз-кандидат под Linux**: нода (nexxusd) + монитор (nexxus-desktop) в .deb/AppImage, CI собирает артефакты.

## Что уже в RC1-базе (verified 11.11)
- **R1 DONE** (`10400d5`): BIP39 API + UI панель сид-фразы. Живой смоук: status / export(confirm) / refuse / import=already.
- **R2 DONE** (`84f0cd0`): seed.vault (AES-256-GCM, PBKDF2 600k, 0600, SDK-формат) + duress-PIN → алерт в Telegram. 6/6 тестов, живой смоук полного цикла.

- Дашборд Phase B: 8 вкладок, все панели через `node_api_cmd`, NodeID-hero, конфиг, юнит, логи, Telegram-настройки.
- Онбординг C1 (машина состояний) + панель Telegram (C-часть).
- 138 тестов workspace зелёные, clippy 0, npm 5/5, desktop 19/19 (после фикса гонки env — общий `TEST_ENV_LOCK`).

## RC1 scope (обязательно)

### R1. Идентичность: BIP39 в UI (v3 Task C2)
- API ноды: `node_identity_status`, `node_identity_export {confirm}` (сид — один раз, не в лог).
- `identity_store.rs`: `export_mnemonic(confirm)`, `import_mnemonic` (refuse поверх существующего стора без явного подтверждения со старым/новым node_id).
- UI: генерация 12/24 слов, восстановление, QR сида, чекбокс «записал», verification challenges из вендоренного `keys::verification`.
- Ворота: тесты roundtrip node_id, отказ без confirm, challenges; clippy; живой смоук export→reinit→тот же node_id.

### R2. Бэкап сид-фразы (v3 Task C3)
- Вендоренный `keys::vault` (AES-256-GCM, PBKDF2 600k, SDK-совместимый формат) → `seed.vault` рядом со стором.
- UI: создать бэкап (PIN + duress PIN), восстановление, индикатор duress → ложный успех + запись в лог/Telegram.
- Тесты: roundtrip, неверный PIN, tamper → AeadAuthFailed.

### R3. Бэкап store + doctor (v3 D1 + D3)
- `node_backup`/`node_restore` в API: redb online backup + манифест (merkle root, sha256), верификация при restore.
- UI-панель «Бэкапы»: создать/список/проверить/восстановить (двойное подтверждение).
- `nexxusd doctor`: порты, права 0600, целостность стора, Tor, диск; монитор показывает в панели здоровья.
- Тесты: бэкап→порча→restore отказывает; бэкап→restore на чистый стор→node_id совпадает.

### R4. Экономика в дашборде (v3 E1)
- API `node_econ`: vesting progress, секции, health/degradation, анти-луп инвариант как индикатор.
- UI: прогресс-бар вестинга (56 дн), карточки секций, health-meter.
- Тест: `node_econ_reports_anti_loop_true`.

### R5. CI + артефакты RC1 (v3 G1-fix + G5-linux + G3)
- CI: добавить сборку `nexxus-desktop --release` и артефакты (nexxusd, nexxus-desktop, .deb, AppImage) в release job.
- Golden vectors: расширить `nexxus-vectors/` на все опкоды 0x01–0x0D, тест в Rust читает те же JSON.
- Пакеты: .deb (есть) + AppImage; smoke на чистой VM/контейнере.

### R6. Чистка и документация
- Убрать `#[allow(dead_code)]`-островки в guardian.rs/api_client.rs (или подключить, или удалить — по правилу аудита).
- `docs/monitor.md` (руководство пользователя монитора) + README-секция RC1.
- `selftest_cmd` — прогон всех WS-методов из UI с отчётом.

## Вне RC1 (post-RC1, из v3)
D2 автобэкап 3-2-1, E2 таймлайн эпох/кворум, F1–F3 (скоринг пиров, fleet, onion-дашборд), G2 fuzz, G4 self-update, H1 SMP inbox, Windows/Android порты.

## Порядок
R1 → R2 → R3 → R4 → R6 → R5 (CI/пакеты последними, когда код стабилен).

## Definition of Done для RC1
- [ ] Все тесты workspace + desktop зелёные, clippy `-D warnings` = 0 (держать постоянно).
- [ ] Живой смоук: монитор→нода→pause/resume→Telegram→бэкап→restore→doctor.
- [ ] BIP39: создать сид в UI → экспорт → восстановление на чистом сторе даёт тот же node_id.
- [ ] CI релиз собирает .deb + AppImage + бинарники, скачиваемые артефакты запускаются.
- [ ] Ни один секрет (токен, сид, PIN) не в git/логах — secret-scan в CI.
- [ ] Документация: установка, онбординг, бэкап, Telegram, doctor.
