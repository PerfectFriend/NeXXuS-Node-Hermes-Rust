## 1. Первый запуск

```bash
# Активировать окружение разработки
source ~/build/env.sh

# Проверить конфигурацию ролей
python3 ~/LivingCode/orchestration/scripts/check_roster.py --update

# Запустить верификацию
bash ~/LivingCode/orchestration/bin/verify.sh

# Убедиться, что выводится «нет проблем»
```

Если всё прошло успешно — готовы к работе с Протоколом Живого Кода.

## 2. Работа с кронами и задачами

Все задачи настраиваются в `orchestration/jobs/jobs.json`. Каждая задача имеет:
- `name` — имя крона (например, `LV-coder-superguard`)
- `schedule` — cron-выражение (например, `0 * * * *` для каждого часа)
- `enabled` — активна ли задача
- `model` — модель LLM (из белого списка)
- `script` — путь к обёртке (если нет — агент запускается через Hermes)

### Проверить статус всех задач:
```bash
python3 ~/LivingCode/orchestration/scripts/check_roster.py --update
```

### Включить задачу:
Отредактировать `jobs.json`, установить `enabled: true`, затем скопировать в `~/.hermes/cron/jobs.json`.

## 3. Как работать с вердиктами Владыки

Владыка Кода (`LV-lord-of-code`) выносит вердикты в `journal.md`:

| Вердикт | Значение | Что делать |
|---------|----------|------------|
| ГОРЯЧИЙ | Проект готов к релизу | Запустить `release_project.py <проект>` |
| ХОЛОДНЫЙ | Проект в разработке | Продолжить работу кодера |
| ВЕРНУТЬ | Нужны доработки | Кодер исправляет ошибки |

### Пример записи в journal.md:
```
[TRIGGER_LORD] superguard — ВЕРДИКТ: superguard — ГОРЯЧИЙ
```

## 4. Как запустить релиз проекта

```bash
# Запустить авто-релиз для проекта
python3 ~/LivingCode/orchestration/scripts/release_project.py superguard

# Для других проектов:
python3 ~/LivingCode/orchestration/scripts/release_project.py elemental-life
python3 ~/LivingCode/orchestration/scripts/release_project.py cybertarot
python3 ~/LivingCode/orchestration/scripts/release_project.py elemental-life-2
```

Скрипт выполнит:
1. Проверку вердикта Владыки (должен быть ГОРЯЧИЙ)
2. Чек-лист релиза (код холодный, нет uncommitted, check_roster rc=0)
3. Определение версии vX.Y.Z
4. Тегирование и пуш в GitHub
5. Экспорт APK в `~/apkexport/`
6. Отчёт в `reports/`
7. Доставку в топик 252 (если настроен CATHEDRAL_BOT_TOKEN)

## 5. Как сформировать MEDIA отчёт

```bash
# MEDIA отчёт для проекта (все три роли: artist, musician, producer)
python3 ~/LivingCode/orchestration/scripts/media_contract.py superguard
```

Отчёт сохраняется в `reports/media-{proj}-{ts}.md` и содержит:
- Количество ассетов художника
- Количество аудио-файлов музыканта
- Количество APK продюсера
- Информацию о логе-квитанции

## 6. Как добавить нового кодера

1. Создать директорию проекта в `Projects/<имя>/`
2. Добавить задачу в `jobs.json` с именем `LV-coder-<имя>`
3. Создать промпт в `scripts/wrappers/prompts/<имя>.txt`
4. Запустить `check_roster.py --update` для проверки
5. Запустить `verify.sh` для верификации

---

## 7. Как обновить промпт роли

Промпты ролей хранятся в `scripts/wrappers/prompts/`. Для обновления:
1. Отредактировать файл промпта
2. Добавить подробные комментарии (для новых кодеров)
3. Сохранить изменения
4. Перезапустить соответствующий крон

## 8. Частые проблемы и их решение

| Проблема | Решение |
|----------|---------|
| `CATHEDRAL_BOT_TOKEN` не задан | Добавить токен в переменные окружения: `export CATHEDRAL_BOT_TOKEN="..."` |
| Отчёты не доставляются в топик 252 | Проверить `TELEGRAM_CRON_THREAD_ID=252` и токен бота |
| Uncommitted-изменения в проектах | Сделать `git commit` в директории проекта перед релизом |
| check_roster ошибки | Исправить `jobs.json` и скопировать в `~/.hermes/cron/jobs.json` |
| Кроны на паузе | Установить `enabled: true` в `jobs.json` |
| Ошибка Windows-пути в коде | Заменить `C:/...` на `/home/thomas/...` |

## 9. Прямая помощь

Если что-то не работает:
1. Проверьте логи в `~/.hermes/cron/errors.log`
2. Проверьте отчёты в `reports/`
3. Проверьте `journal.md` на вердикты и триггеры
4. Убедитесь, что `verify.sh` выводит «нет проблем»
